# V1 实施路线

V1 围绕任务接续与交付推进：先从当前目录开始并完成人工任务，再证明日常恢复价值，然后接入现有 AI 会话。自动执行控制需要额外的用户需求证据；知识和优化不属于 V1 发布承诺。

## 准备：冻结最小切片

- 选取至少 5 个真实任务，记录现有接续耗时、重复解释和证据定位困难。
- 冻结 Task/Review/TaskCheckpoint 最小模型，以及默认 Workspace 与当前目录 Repo/Worktree 的身份规则。
- 选择技术栈、首个支持平台、嵌入式核心或本地服务；不以三平台全覆盖阻塞第一轮试用。
- 选择最小证据表示与明确停写的维护备份方案，关闭恢复 generation 和 Review 编辑失效问题。
- 明确 V0 数据是否需要导入；没有实际迁移需求时不实现 Markdown importer 或兼容框架。

退出条件：能用一条具体用户路径说明首版结果，没有必须先建设独立 Registry、控制 Agent 或建立知识系统的依赖。

## 阶段 A：首个可用版本

交付：

- CLI 创建、选择、查看、更新、阻塞、提交验收、返工和归档任务。
- 默认 Workspace；按当前目录识别 Repo/Worktree，并保存显式 TaskContextBinding。
- 目标、owner、唯一下一步、验收标准、进度、来源可追溯的关键决策和最小证据。
- 不依赖 AI 的 TaskCheckpoint create/list/show 与恢复上下文查询。
- SQLite 事务、版本冲突、幂等、事件时间线和维护备份恢复。
- 使用 Blob 时落实发布先于引用与证据保留，不提前实现在线备份和实现快照采集。

退出条件：用户能从当前目录开始一个真实任务，中断后找回下一步，并检查证据、显式验收或返工；创建任务不要求完成 Workspace onboarding。重启、冲突和备份恢复的关键检查通过。

## 阶段 B：日常使用版本

交付：

- 当前任务发现、多任务选择、最近 Checkpoint 与当前 Task/Git 差异展示。
- 一个薄 TUI 或 GUI，覆盖任务列表、详情、接续和验收；CLI 保持完整闭环。
- 简单项目约束、关键决策和操作说明的人工关联复用。
- missing Worktree、证据不可读、部分 Checkpoint 和过期版本的可恢复反馈。

退出条件：至少 5 个真实样本完成隔日接续演练，按第 02 篇记录恢复耗时、重复解释与失败原因；多数样本无需重读完整聊天即可确认下一步。未达到目标时优先修复恢复体验，不用新增看板或自动化替代验证。

暂缓：复杂依赖图、SavedView、周期任务、模板、批量编辑、通知、智能 Next Action、第二套完整客户端。需要时逐项列出实际使用依据。

## 阶段 C：接入现有 AI 会话

交付：

- CLI/MCP 读取当前任务、约束、决策、Checkpoint 与证据引用。
- AI 使用受控身份和 Task scope 写入进度、阻塞、Checkpoint 和完成候选。
- 现有会话结束或更换后，新会话重新读取当前状态与权限继续工作。
- 最小交接记录和按需证据，不默认采集完整会话或接管宿主上下文压缩。
- 用户验收和 Task 状态机继续共用同一核心。

退出条件：新会话能根据产品提供的信息说清目标、限制、证据和下一步，并继续一个真实任务；记录重复解释次数并与准备阶段比较。过期权限、版本冲突、重复写入被拒绝或幂等收敛；AI 不能自动关闭任务。

阶段 C 完成且 A/B 仍可独立使用后，可评估发布 V1。发布不要求自动 spawn、多 Runtime、Git 写入、完整 BusinessFact 或 Optimizer。

## 阶段 D：可选执行增强

进入条件：阶段 C 已日用，手动启动、恢复或管理 Agent 已形成反复出现的明确成本，且用户决定由产品接管这部分动作。

- 选择一个 Runtime，验证 capability 与宿主集成方式；Herdr、Pi、Claude、Codex 均为候选，不要求同时支持。
- 按需要实现 Assignment、AgentRun、RuntimeOperation、固定目标、ordering scope 和 reconcile。
- ContextWindow、History、WorkingNote 仅实现所选 Runtime 需要的部分；任务接续继续依赖 TaskCheckpoint。
- 外部副作用必须覆盖响应丢失、崩溃、重复请求和未知结果；不能以“先做简单版”绕过这些约束。

退出条件：相较阶段 C 有明确操作成本下降，且已控制的外部副作用不会因重试重复执行。更多 Runtime、Git 写操作和 Hardened 各自评估，不自动纳入本阶段。

## 探索 X：知识与优化

不设为 V1 退出条件，不预先承诺版本号。分别验证：

- 简单约束与决策被频繁复用后，结构化 BusinessFact 是否减少维护成本。
- 用户是否确实需要跨分支实现映射与漂移检查，且愿意维护扫描范围和确认结果。
- 已有返工、澄清和交接损失记录是否足以评估优化候选的收益。

仅在问题成立后分别立项。完整会话采集、长期索引和 embedding 必须有具体用途、范围、保留策略与授权；不能仅因以后可能用于学习而默认采集。

## 发布与范围控制

- 阶段 A/B/C 表示用户能力，不沿用旧规划的 0.1 Registry、0.2 Task、0.3 Runtime 编号。
- 实际版本号根据已交付范围和接口稳定性确定，V1 主线为 A–C。
- 每轮评估同时检查正确性、恢复成功率、用户耗时与重复解释；未验证结果不得写成已完成收益。
- 任何新增实体、后台服务或集成先说明其支持的用户路径和阶段，不能因为模型文档已有定义就进入实现。
