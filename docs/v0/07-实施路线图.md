# 实施路线图

## D0：设计收敛

交付：

- Task、Session、Checkpoint、Note 和 History 的 SQLite Schema；
- `claim`、`checkpoint`、`resume` 的行为合同；
- SQLite migration、事务、外键和并发冲突规则；
- 轻量 Worktree 命令与最低保护；
- AI 主动调用 CLI 的会话协议；
- Client Hook / Runtime Adapter 的后续边界。

退出条件：所有初版命令都能对应到明确数据字段，不依赖 Owner、Assignment、Event 或 Operation 等未实现模型。

## M1：Task CLI

实现：

- `task create/list/show/update/note/block/close`；
- Rust Cargo workspace 和同步 SQLite Adapter；
- SQLite 初始化、内嵌 migration 和 Schema version；
- Task mutation、乐观 version 与事务化 History；
- 稳定 `--json` 输出；
- `doctor`。

## M2：Session 连续性

实现：

- `task claim/checkpoint/resume`；
- `session list/show/attach/import/close`；
- 本地 Session ID 和可选外部 Session ID；
- `continuedFrom`、Session 历史和最新 Checkpoint；
- 新 Session 恢复 Task、Checkpoint 和 Git 现场；
- 项目 `AGENTS.md` 的 AI 更新协议示例。

完整聊天自动采集不属于此阶段。

## M3：轻量 Worktree

实现：

- `worktree create/status/remove`；
- Repository、Branch、Worktree 引用写入 Task；
- HEAD、dirty、staged 和 untracked 实时观察；
- dirty Worktree 默认拒绝删除；
- 使用临时 Git 仓库完成端到端测试。

此阶段不实现 plan/execute/reconcile，不提供 push、force、clean、reset 或隐式 stash。

## M4：AI Client Hook / Runtime Adapter

在手工 CLI 闭环稳定后实现：

- Session start、resume、idle、close 生命周期上报；
- 客户端实际暴露的消息和工具事件采集；
- 来源事件 ID 和幂等导入；
- 落盘前脱敏；
- Hook 不可用时退回显式 CLI；
- Hook 只更新 Session 记录，不自动改变 Task 状态或关闭结果。

不同 AI 客户端通过窄 Runtime Adapter 接入，不在 Core 中加入客户端特有逻辑。

## M5：本地 Daemon 与 GUI

实现：

- 复用 Rust Application Service 和 SQLite Repository 的本地 Daemon；
- HTTP Query/Command API；
- 任务列表、详情、Checkpoint、Session 历史和 Worktree 状态；
- loopback 限制；
- 是否增加实时事件订阅由 Hook 使用需求决定。

## 后续按需评估

只有出现真实场景后再评估：

- 多 Agent Assignment 和角色编排；
- Owner/Ownership 权限模型；
- 外部操作的持久化恢复；
- Approval 和远程写入；
- SQLite 备份、导入导出、全文搜索和复杂查询优化。

## 首个纵向用例

1. 使用临时 SQLite 数据库，在任务创建窗口由 AI 创建 synthetic Task；
2. 在执行窗口用 Session A 领取 Task；
3. 创建临时 Repository 和 Worktree；
4. AI 更新进度、决策和阻塞；
5. Session A 保存 Checkpoint；
6. 新窗口用 Session B `resume`；
7. CLI 返回 Task、Checkpoint、Session 历史和实时 Git 状态；
8. Session B 继续并关闭 Task；
9. History 可以重放上述关键变化。

全过程只使用临时 SQLite 数据库和临时仓库，不接触用户默认数据库或真实业务项目。
