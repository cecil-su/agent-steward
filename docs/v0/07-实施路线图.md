# 实施路线图

> 本路线图只定义 V0 内部的 D0、M1–M5 和后续评估项。它不构成通往 V1 或未来 V2 的升级路径，各里程碑状态也不得计入其它版本方案的完成度。

## D0：设计收敛

交付：

- Task、Session、Checkpoint、Note 和 History 的 SQLite Schema；
- Task Create/Patch、Checkpoint 和稳定 JSON envelope/DTO；
- Task 状态转换、Session close/take-over、目标 Session 生命周期和同 Task 引用不变量；
- `claim`、`checkpoint`、`resume` 的行为合同；
- SQLite 初始化、事务、外键和并发冲突规则；
- 稳定错误/警告码（包括 Git 执行失败）、同状态 no-op 与 stale replay 规则；
- 轻量 Worktree 命令、最低保护和部分完成后的 adopt/detach 恢复合同；
- CanonicalPath、RepositoryIdentity 和 Git 操作前后复核合同；
- AI 主动调用 CLI 的会话协议；
- Client Hook / Runtime Adapter 的后续边界。

退出条件：所有初版命令都能对应到明确输入 DTO、状态转换、数据字段、错误码和验收用例，不依赖 Owner、Assignment、Event 或 Operation 等未实现模型。

## M1：Task CLI

实现：

- `task create/list/show/update/note/block/unblock/close`；
- Rust Cargo workspace 和同步 SQLite Adapter；
- SQLite 单一 Schema 原子初始化和 `user_version` 标识；
- 调用方 expected version、compare-and-swap 与事务化 History；
- 已版本化的稳定 `--json` envelope、DTO 和错误码；
- `doctor`。

## M2：Session 连续性

实现：

- `task claim/checkpoint/resume`；
- `session list/show/attach/import add/import list/import remove/close`；
- 本地 Session ID 和可选外部 Session ID；
- `continuedFrom`、Session 历史和最新 Checkpoint；
- claim/resume 新 Session ID、已结束 Session 禁止重激活和稳定 Session 排序规则；
- `session close` 对当前 Session 引用的原子清理；
- Session 导入目标、16 MiB 上限、普通文件校验、有界哈希、SHA-256 去重和逻辑删除；
- 新 Session 恢复 Task、Checkpoint 和 Git 现场；
- 项目 `AGENTS.md` 的 AI 更新协议示例。

完整聊天自动采集不属于此阶段。

## M3：轻量 Worktree

实现：

- `worktree create/status/remove/adopt/detach`；
- 重复 create 在 Git 调用前拒绝，禁止覆盖已有 Repository/Worktree 引用；
- 按 Task 的跨进程 advisory lock 和 Worktree 路径数据库唯一约束；
- Repository 路径、规范化 common-dir 身份、Branch 和 Worktree 引用写入 Task；
- 跨平台 CanonicalPath、Git common-dir RepositoryIdentity 和 TOCTOU 复核；
- Git 任意退出状态后的现场重观测，以及 `GIT_COMMAND_FAILED`/`PARTIAL_EXTERNAL_STATE` 分类；
- 只使用已存在本地分支，不隐式创建 Branch；
- HEAD、dirty、staged 和 untracked 实时观察；
- dirty Worktree 默认拒绝删除；
- 使用临时 Git 仓库完成端到端测试。

此阶段不实现通用 plan/execute/reconcile 状态机；adopt/detach 只修复经过现场证明的 Worktree 引用，不提供 push、force、clean、reset 或隐式 stash。

## M4：AI Client Hook / Runtime Adapter

在手工 CLI 闭环稳定后实现：

- Session start、resume、idle、close 生命周期上报；
- 客户端实际暴露的消息和工具事件采集；
- 来源事件 ID 和幂等导入；
- 落盘前脱敏；
- Hook 不可用时退回显式 CLI；
- Hook 只更新 Session 记录，不自动改变 Task 状态或关闭结果。

不同 AI 客户端通过窄 Runtime Adapter 接入，不在 Core 中加入客户端特有逻辑。

## M5：本地 Daemon 与 GUI

实现：

- 复用 Rust Application Service 和 SQLite Repository 的本地 Daemon；
- HTTP Query/Command API；
- 任务列表、详情、Checkpoint、Session 历史和 Worktree 状态；
- loopback 限制；
- 每次启动生成的认证秘密或等价的同用户本地认证；
- Host/Origin 校验、CORS 拒绝默认和 mutation CSRF 防护；
- 是否增加实时事件订阅由 Hook 使用需求决定。

## 后续按需评估

只有出现真实场景后再评估：

- 多 Agent Assignment 和角色编排；
- Owner/Ownership 权限模型；
- Worktree 引用修复之外的外部操作持久化恢复；
- Approval 和远程写入；
- SQLite 备份、导入导出、全文搜索和复杂查询优化。

## 首个纵向用例

1. 使用临时 SQLite 数据库，在任务创建窗口由 AI 创建 synthetic Task；
2. 在执行窗口读取 Task version，再用 Session A 领取 Task；
3. 创建临时 Repository 和 Worktree；
4. AI 更新进度、决策和阻塞；
5. Session A 保存 Checkpoint；
6. 新窗口用 Session B `resume`；
7. CLI 返回 Task、Checkpoint、Session 历史和实时 Git 状态；
8. Session B 继续并关闭 Task；
9. History 可以按 sequence 查询上述关键变化；
10. 人为注入 Git 成功、SQLite 失败，分别使用 `worktree adopt` 和 `worktree detach` 恢复引用一致性；
11. 使用路径别名验证 Repository/Worktree 身份一致，再导入、去重查询并逻辑删除一份 synthetic Session 文件。

全过程只使用临时 SQLite 数据库和临时仓库，不接触用户默认数据库或真实业务项目。
