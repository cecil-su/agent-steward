# 删除任务与需求

## 语义与范围

- **任务删除为服务端逻辑删除**，不是 `cancelled` 或 `done`，也不是仅在页面隐藏。七种业务状态均可删除；删除只递增 Task version/updatedAt 并追加 `task.deleted` History，不改变 status、关闭字段、项目归属或任何 Session。
- 正常任务列表、搜索、项目任务列表和看板分页不再返回已删除任务；页面数量由这些查询结果更新。普通详情、context、work、Notes、History 和后续 Task 写入返回 `TASK_DELETED`，通过明确的只读审计入口查看保留内容。
- **单需求删除**从最新权威 work 快照移除目标，保留其他需求。不是将需求标记为 cancelled。共享确认项只去除目标 requirementId，保留问答和其余关联；独占该需求的确认项从当前快照一并移除。历史问答仍在旧快照，不伪造已答复或撤回状态。
- 删除最后一个需求后，返回格式1的空 work，不返回代表“尚未整理”的 `null`。已删除需求及被移出的确认项 ID 不可复用；后续 `work-update` 不能借旧 ID 复活或重新解释原对象。
- 不修改任务说明、Notes、Checkpoint、evidence 中的历史文字，不进行全文追删。没有永久清除、自动清理、批量删除、恢复功能或回收站。

## 关联数据保护

整任务有**任一 `endedAt IS NULL` 的 Session**时返回 `DELETE_BLOCKED`。不仅检查 currentSession：已被 take-over 但未结束的旧 Session 仍受保护。宿主离线、Task 终态或观测 closed 事件不代表 Session 已结束。删除不会 close、resume 或 take-over Session，更不会终止宿主 Agent。用户需通过独立明确操作处理会话。

单需求删除不改变或结束当前 Session，使用 Task CAS 与其他 Agent 写入竞争。

任务逻辑删除后保留：

| 内容 | 行为 |
| --- | --- |
| Task、task_components | 保留原身份和关联，ID/taskKey 不复用 |
| Notes、Checkpoint、完整 History、work 旧快照 | 原文和原序号保留；只追加删除记录 |
| 已结束 Session、continuedFrom、Import BLOB、Hook 事件/去重键 | 不清理；禁止对已删除任务继续 Import/clear/bind/ingest 等写入 |
| 项目资料和规则来源 | 保留原来源 Task ID/记录版本/证据，不改变 Project/Rule revision 或旧 History |
| 外部文件、Pi 会话记录、任务资源目录、备份 | 不访问或删除 |

项目资料返回可选 `sourceTaskDeletion`，规则视图返回非空时的 `deletedSourceTaskIds`，仅派生显示，不替换原来源内容。来源历史读取与 Task 业务写入区分：项目/规则仍可显式维护历史来源，不会因此复活原任务。普通 Task 写入口统一拒绝。

逻辑删除的数据仍在 SQLite 并占空间，不提供隐私擦除保证。只读角色仍能使用显式审计接口；删除不是撤销读权限。

## CLI 与 HTTP

所有写入要求当前版本、非空原因及显式确认。示例 DB 必须是明确指定的隔离库，编号和版本来自该库读取：

```text
taskctl --database DB --json task delete-preview TASK
taskctl --database DB --json --yes task delete TASK --if-version VERSION --reason "原因"
taskctl --database DB --json task audit TASK

taskctl --database DB --json task requirement-delete-preview TASK REQUIREMENT_ID
taskctl --database DB --json --yes task requirement-delete TASK REQUIREMENT_ID --if-version VERSION --reason "原因"
```

| HTTP | 合同 |
| --- | --- |
| `GET /api/tasks/{id}/delete-preview` | task/当前版本、logical 模式、保留数量、未结束 Session、项目/规则来源引用及 blocked |
| `GET /api/tasks/{id}/requirements/{requirementId}/delete-preview` | task、目标需求、将移出的独占确认和调整关联的共享确认 |
| `POST /api/commands/task-delete` | `{taskId,expectedVersion,confirmed:true,reason}` |
| `POST /api/commands/task-requirement-delete` | `{taskId,expectedVersion,requirementId,confirmed:true,reason}` |
| `GET /api/tasks/{id}/audit` | 显式只读读取 task/deletion/work/完整 history/notes/checkpoints/sessions，支持已删除任务，不含 Import BLOB |

历史 Session 的按 ID GET、Hook 分页和 Import 元数据读取仍可只读审计，返回 `deletion` 标识（未删除时为 null）；全局正常 Session 列表排除已删除任务。审计不提供新的写入或恢复权限。

`TASK_DELETED` 返回 HTTP 410；`DELETE_BLOCKED`、`WORK_ITEM_DELETED` 和版本冲突返回409；未找到需求返回404。未知字段、未确认或无效原因返回400。沿用管理员、Host/Origin、CSRF、UI合同及结构化错误边界，reader 不可写。

预览不是执行凭据。写事务取得 IMMEDIATE 锁后重新读取目标、检查 CAS、Session/引用和 work 完整性；Task version 与 History 同事务提交。失败回滚，重复删除不新增事件，冲突或响应丢失不自动重试。

任务删除事件的 payload 为 `deletedAt/reason/previousVersion`。需求删除继续追加 `task.work_updated`，包含新的完整 work、reason、`operation=requirement_deleted`、`deletedRequirementId`、`changedRequirementIds/changedConfirmationIds/removedConfirmationIds`。旧快照不改写。

## 页面

原生任务详情的危险按钮为“删除任务”，单需求卡片为“删除需求”；列表详情和看板抽屉共用渲染。只有管理员且 `/api/access` 分别提供 `taskDeletion:true` / `requirementDeletion:true` 才显示对应入口。旧后端不显示不可用操作，React 回退仍为业务只读。

确认框展示任务编号、标题、版本、需求编号、实际影响和保留说明，要求填写原因并勾选确认。未结束 Session 显示阻止原因；取消不发送写请求。提交单飞，处理中不允许取消掩盖请求，冲突、失败或未知结果禁用原提交，必须关闭并重新读取影响，不自动套用新版本。成功刷新列表、看板数量及需求详情；已写入但刷新失败单独提示，不建议重复删除。已删除任务可显式查看只读审计，来源链接显示删除标识。审计与普通详情分别保存选择模式，手动刷新、SSE更新/重连和返回任务页按模式重读，保留审计展开项；切换任务/布局或退出连接清理模式，迟到响应不能覆盖新选择；列表刷新未结束时已导航到项目页，则不恢复旧审计或强制切回任务页。每条历史Checkpoint可展开读取身份、会话、时间及完整摘要、已完成、决策、待办、风险、下一步和已有gitHead。

## 兼容、发布与验证入口

保持 Schema8、envelope3、UI合同5、包格式1；没有数据库迁移或原地结构修改。删除语义由新版 Application/CLI/taskd 实现，**旧可执行程序不能识别 History 删除标记，不得继续作为配套读写入口**。正式启用前需同时核实 CLI、taskd 及相关宿主写入口使用支持删除保护的版本；仅换 UI 不足以提供后端保护。兼容的新旧页面靠能力字段和现有合同区分。源码/构建不代表已部署，不自动同步 embedded 或激活活动 UI。

隔离回归入口：

```text
cargo test -p steward-application --test task_deletion
cargo test -p taskctl --test task_deletion
cargo test -p steward-server --test task_deletion
cd web
npm test -- src/lib/native-deletion.test.ts
npm run typecheck
```
