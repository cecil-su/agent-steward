# 数据模型与存储

## 1. 存储基线

初版使用本机 SQLite 数据库作为唯一主存储，不使用 Markdown、JSON 或 JSONL 文件保存权威任务数据，也不需要独立数据库服务。SQLite 数据库不用于多台机器共享。

默认数据库路径：

- Windows：`%LOCALAPPDATA%\agent-steward\steward.db`；
- macOS：`~/Library/Application Support/agent-steward/steward.db`；
- Linux：`${XDG_DATA_HOME:-~/.local/share}/agent-steward/steward.db`。

用户可以通过全局选项 `--database <path>` 覆盖默认路径。测试必须使用临时数据库，不能读写用户默认数据库。

每个连接至少设置：

```sql
PRAGMA foreign_keys = ON;
PRAGMA journal_mode = WAL;
PRAGMA busy_timeout = 5000;
```

初版由 Rust CLI 使用同步 SQLite Adapter 直接访问数据库。Markdown 和 JSON 只可作为显式 `--input`、导入或未来导出格式，不能绕过 Application Service 修改数据库。

## 2. Schema

数据库包含以下初版表。所有时间使用 UTC RFC 3339 字符串；所有布尔语义使用 `0/1`；JSON 字段由 Application Service 在写入前校验。

### `schema_migrations`

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `version` | INTEGER | PRIMARY KEY |
| `description` | TEXT | NOT NULL |
| `applied_at` | TEXT | NOT NULL |

migration 以递增版本内嵌在应用中。应用发现数据库版本高于自身支持版本时必须拒绝写入，不能自动降级。

### `tasks`

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | TEXT | PRIMARY KEY |
| `title` | TEXT | NOT NULL |
| `status` | TEXT | NOT NULL，`open/in_progress/blocked/closed` |
| `version` | INTEGER | NOT NULL，初始为 1 |
| `goal` | TEXT | NOT NULL |
| `scope` | TEXT | NOT NULL |
| `acceptance_criteria` | TEXT | NOT NULL |
| `next_step` | TEXT | NULL |
| `block_reason` | TEXT | NULL |
| `block_recovery` | TEXT | NULL |
| `current_session_id` | TEXT | NULL，引用 `sessions.id` |
| `repository_path` | TEXT | NULL |
| `repository_branch` | TEXT | NULL |
| `worktree_path` | TEXT | NULL |
| `latest_checkpoint_id` | TEXT | NULL，引用 `checkpoints.id` |
| `closure_outcome` | TEXT | NULL，`completed/partial/cancelled/superseded` |
| `closure_reason` | TEXT | NULL |
| `closed_at` | TEXT | NULL |
| `created_at` | TEXT | NOT NULL |
| `updated_at` | TEXT | NOT NULL |

`current_session_id` 和 `latest_checkpoint_id` 的外键应为可延迟约束，使 Task 与子记录可以在同一事务中一致更新。`acceptance_criteria` 保存人类可读文本，不要求把每条标准拆成独立表。

### `sessions`

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | TEXT | PRIMARY KEY |
| `task_id` | TEXT | NOT NULL，引用 `tasks.id` |
| `source` | TEXT | NULL |
| `external_session_id` | TEXT | NULL |
| `continued_from` | TEXT | NULL，引用 `sessions.id` |
| `record_path` | TEXT | NULL |
| `started_at` | TEXT | NOT NULL |
| `ended_at` | TEXT | NULL |

`record_path` 只是用户明确提供的外部记录引用，不表示文件内容已进入数据库。相同 `source + external_session_id` 在外部 ID 非空时应保持唯一。

### `checkpoints`

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | TEXT | PRIMARY KEY |
| `task_id` | TEXT | NOT NULL，引用 `tasks.id` |
| `session_id` | TEXT | NOT NULL，引用 `sessions.id` |
| `summary` | TEXT | NOT NULL |
| `completed_json` | TEXT | NOT NULL，JSON array |
| `decisions_json` | TEXT | NOT NULL，JSON array |
| `pending_json` | TEXT | NOT NULL，JSON array |
| `next_step` | TEXT | NOT NULL |
| `risks_json` | TEXT | NOT NULL，JSON array |
| `git_head` | TEXT | NULL，仅为创建时观察快照 |
| `created_at` | TEXT | NOT NULL |

Checkpoint 的 `git_head` 用于恢复提示，不是当前 Git 状态的权威来源。

### `task_notes`

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT |
| `task_id` | TEXT | NOT NULL，引用 `tasks.id` |
| `session_id` | TEXT | NULL，引用 `sessions.id` |
| `note_type` | TEXT | NOT NULL，`decision/progress/risk` |
| `text` | TEXT | NOT NULL |
| `created_at` | TEXT | NOT NULL |

### `history`

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT |
| `task_id` | TEXT | NOT NULL，引用 `tasks.id` |
| `sequence` | INTEGER | NOT NULL |
| `change_type` | TEXT | NOT NULL |
| `session_id` | TEXT | NULL，引用 `sessions.id` |
| `occurred_at` | TEXT | NOT NULL |
| `summary` | TEXT | NOT NULL |
| `payload_json` | TEXT | NULL |

`UNIQUE(task_id, sequence)` 保证单个 Task 的 History 顺序唯一。sequence 必须在同一写事务内分配。

建议变更类型：`task.created`、`task.claimed`、`task.updated`、`task.blocked`、`checkpoint.saved`、`session.resumed`、`worktree.created`、`worktree.removed`、`task.closed`。

### `session_imports`

该表仅用于用户明确执行 `session import` 时保存导入副本，不要求初版自动解析完整聊天。

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `id` | TEXT | PRIMARY KEY |
| `session_id` | TEXT | NOT NULL，引用 `sessions.id` |
| `source_path` | TEXT | NULL |
| `media_type` | TEXT | NULL |
| `sha256` | TEXT | NOT NULL |
| `content` | BLOB | NOT NULL |
| `imported_at` | TEXT | NOT NULL |

导入内容不参与 Task 状态推断。用户必须在导入前检查敏感信息；普通 `session attach --record-path` 只保存路径，不复制文件。

## 3. 索引

初版至少建立：

- `tasks(status, updated_at)`；
- `sessions(task_id, started_at)`；
- `checkpoints(task_id, created_at)`；
- `task_notes(task_id, created_at)`；
- `history(task_id, sequence)`；
- `session_imports(session_id, imported_at)`；
- `sessions(source, external_session_id)` 的非空唯一索引。

只为已定义的查询建立索引，不提前引入全文索引或复杂搜索表。

## 4. 核心模型

### Task

- 目标、范围、状态和验收条件；
- 当前 Session 和 Session 历史；Session 历史通过 `sessions.task_id` 查询，不在 Task 中重复保存数组；
- 当前步骤、阻塞、备注和关闭结果；
- Repository、Branch 和 Worktree 引用；
- 最新 Checkpoint 引用和递增版本。

### Session

Session 是一次 AI 会话的引用和连续性记录，不等于完整聊天副本。`continued_from` 形成明确的继续关系；没有外部 Session ID 时使用本地稳定 ID。

### Checkpoint

Checkpoint 保存新 Session 恢复所需的显式事实，不保存或推断隐藏推理。数组字段在 Rust Core 中使用结构化集合，在 SQLite 中以经过校验的 JSON 保存。

### History

History 是重要 mutation 的顺序记录。它与对应业务变更在同一 SQLite 事务中提交；History 插入失败时整个 mutation 回滚，不能返回“业务成功但历史缺失”。

## 5. 事务合同

每次数据库 mutation 必须：

1. 开启写事务；
2. 在事务内读取 Task 和当前 `version`；
3. 校验状态、Session 和外键关系；
4. 写入 Task、Session、Checkpoint 或 Note；
5. 使用预期 version 更新 Task，并递增 version；
6. 分配并插入下一条 History；
7. 全部成功后提交，否则全部回滚。

建议写事务使用 `BEGIN IMMEDIATE`。如果预期 version 不匹配、数据库繁忙超过 timeout 或当前 Session 冲突，返回明确冲突，不覆盖新版本。

`resume` 等需要一致读取多个表的 Query 应使用只读事务获得数据库快照。Git 观察必须在数据库写事务之外执行，避免长时间持有写锁。

## 6. Git 外部操作边界

SQLite 事务不能与 Git 命令组成同一个原子事务：

- Worktree 创建成功后，才在数据库事务中保存引用和 History；
- Git 创建成功但数据库提交失败时，不自动删除现场，必须返回 Worktree 路径和明确修复提示；
- Worktree 删除成功后，才在数据库事务中清除引用；
- Git 删除成功但数据库提交失败时，保留可诊断的陈旧引用并返回错误；
- `doctor` 可以报告引用与真实 Git 现场不一致，但不能擅自修复或删除。

初版不为此引入 Operation Plan；命令不得把部分完成伪装成完整成功。

## 7. Migration 与诊断

- migration SQL 随 Rust 二进制内嵌并按版本顺序执行；
- 每个 migration 在事务中执行，失败时保持原 schema；
- 初版不自动执行不可逆降级；
- `doctor` 至少执行 schema 版本检查、外键检查和 SQLite `quick_check`；
- 数据库损坏、版本过新或 migration 失败时返回明确错误，不自动重建或覆盖用户数据库；
- 备份、导出和恢复命令在出现明确需求后单独设计，不能用直接编辑数据库代替。

## 8. 后续演进

出现以下需求后再扩展：

- AI Client Hook 自动记录 Session 生命周期；
- Runtime Adapter 幂等接收可观察消息和工具事件；
- 本地 Rust Daemon 和 GUI；
- 数据库备份、导入导出和全文搜索；
- 经真实场景验证后的多 Agent、审批或可恢复外部操作模型。

除非产品边界改为跨机器共享，否则不引入 PostgreSQL 或远程数据库服务。
