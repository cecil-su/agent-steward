# 数据模型与存储

## 存储基线

本机单用户SQLite是业务状态唯一主存储，不用Markdown/JSONL作为权威任务库，不支持多机器共享数据库文件。

默认路径：Windows `%LOCALAPPDATA%/agent-steward/steward.db`，macOS `~/Library/Application Support/agent-steward/steward.db`，Linux `${XDG_DATA_HOME:-~/.local/share}/agent-steward/steward.db`。--database可覆盖；测试使用临时库。

当前 `PRAGMA user_version=8`。普通连接只打开当前Schema或对空库在IMMEDIATE事务中初始化，取得写锁后复查版本；非空未标记库/不兼容库拒绝，不自动升级、清空或重建。写事务取得锁后也复核Schema。普通写连接启用foreign_keys、WAL、5000ms busy_timeout；task context使用专用只读连接，不设置WAL或初始化。

Unix应用目录0700、库及WAL/SHM不宽于0600；Windows使用私有DACL。权限不能证明时明确告警/按相应入口拒绝，不宣称内容已加密。迁移只复制到新库，见 [隔离导入](18-Schema7隔离导入与验证.md)。

## Task

TaskView的20个字段及camelCase合同见 [CLI](03-CLI命令设计.md)。SQLite字段使用snake_case：

- id为INTEGER PRIMARY KEY AUTOINCREMENT，不可修改、删除后不复用；task_key可空且唯一，只能首次设置。
- status仅backlog/todo/in_progress/in_review/blocked/done/cancelled，创建todo；version从1递增。任意状态可转为其他状态，无流程前置条件。
- title/goal/scope/acceptance_criteria可初始为空，设置后不可清空；非空值需非空白。title写入时校验命名规则，不改写历史标题。
- next_step可空，任何状态均可维护，不随业务状态变化清除。
- project_id可空；componentIds由task_components关系表派生，不保存第二份数组。
- current_session_id与latest_checkpoint_id通过延迟复合外键引用同Task的Session/Checkpoint。当前Session必须尚未结束。
- block_reason/block_recovery/closure_outcome/closure_reason/closed_at保留旧事实。closure_outcome允许completed/partial/cancelled/superseded或NULL，与status不再有行级耦合；新status命令不生成或清除这些历史字段。
- created_at/updated_at为UTC RFC3339。Task不再保存repository_path/repository_common_dir/repository_branch/worktree_path。

## Session、Checkpoint、Note与History

| 表 | 关键数据与约束 |
| --- | --- |
| sessions | 文本id、task_id、source/external_session_id、continued_from、record_path、started_at/ended_at；外部身份组合唯一，continued_from不能指向自身或跨Task |
| checkpoints | 文本id、task_id/session_id、summary、completed/decisions/pending/risks JSON数组、next_step、git_head、created_at；不可原地修改 |
| task_notes | 自增id、task_id、可空session_id、note_type(decision/progress/risk)、text、created_at |
| history | 自增id、task_id、sequence、change_type、可空session_id、occurred_at、summary、payload_json；UNIQUE(task_id,sequence) |

Session是独立记录，不是业务状态：claim/resume不改status，status不改变Session。旧Session继续关系和endedAt原样保留，不自动恢复。Checkpoint在任意业务状态下都要求同任务未结束的当前Session；git_head仅保留历史，新记录为NULL，不再查询Git。

Note适用于全部状态，无需先领取；原文存储，可安全Markdown展示。Note/History的session_id非空时必须属于同Task。检查点、Note和History JSON损坏时返回错误，不伪造空内容。

同Task复合引用：tasks(current_session_id,id)→sessions(id,task_id)、tasks(latest_checkpoint_id,id)→checkpoints(id,task_id)为DEFERRABLE INITIALLY DEFERRED；sessions/checkpoints/task_notes/history的相应引用也约束task_id一致。Session历史按started_at/id排序，History按sequence排序。

## 项目、源码路径与规则

- projects/project_history：项目独立revision CAS及历史；components：项目内名称唯一；task_components：Task与组件必须属于同项目。
- source_roots仅保存id/project_id/component_id/directory_path/created_at。directory_path是绝对路径文本资料，不查存在性、不canonicalize、不读取源码/Git。repositories表与源码身份/相对路径字段已移除。
- project_profiles：每项目一条当前资料，以Project revision维护，保留sourceTaskId/sourceTaskVersion/evidence；不自动验证正文事实。
- rules/rule_history：独立Rule revision，global/project范围，candidate/active/disabled状态，content_version/content_json与来源。规则状态不是Task状态。

详见 [项目](16-项目与上下文复用.md)、[项目资料](19-项目资料与CLI维护.md)、[规则](22-个人偏好与项目规则.md)。

## 导入内容与观测

session_imports保存id/session_id/source_path/media_type/sha256/content BLOB/imported_at；UNIQUE(session_id,sha256)，sizeBytes由BLOB长度派生。仅显式已审查的普通文件可导入，上限16MiB，有界流式读取；列表不返回正文。删除先secure_delete、同事务写History，提交后尝试WAL truncate；不保证外部备份或介质物理擦除。

session_events有独立sequence与(session_id,event_id)唯一键，保留指纹及kind/occurredAt/receivedAt。clear保留ID/指纹墓碑，其余事件字段置空；事件不改变Task状态/version/History，不执行Session生命周期。容量和隐私见 [Hook合同](11-Hook与HTTP合同.md)。

taskd的identity/browser-sessions.db只保存浏览器授权哈希、角色和有效期，不是第二个业务库。

## 事务与诊断

除create外，Task业务写入：请求expectedVersion→IMMEDIATE事务→读Task/校验CAS及关联→写业务→version+1/updatedAt→分配History sequence并写入→提交。任何失败全部回滚；实际更新需恰好一行。同值no-op也先检查CAS，不写History。Project/Rule使用各自revision，不混用。

status只更新status/version/updatedAt，其他字段不变。claim/resume/checkpoint等身份操作保留独立约束，不再根据业务状态设门槛。Import文件读取在事务外有界进行；响应丢失先重读，不自动重放。

索引覆盖Task状态/项目与更新时间、Session归属/身份、检查点和Note时间、History序号、Import身份/时间及规则上下文；不保留Task仓库索引。doctor检查Schema、quick_check、外键和Session记录路径，不调用Git、不修复用户文件。
