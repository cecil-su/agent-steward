# 安全与事务

## 1. 初版信任模型

M1–M3 CLI 是本地单用户工具，由人决定领取、接管和 Worktree 范围。当前 M5 HTTP 增加 admin/reader 访问角色，不建立领域 Owner、Registry 或 Approval。默认本机直连免凭据会信任本机所有用户/程序；需隔离本机调用或经过代理时使用 `--require-local-auth`。非回环 HTTP 不加密，完整网络、Cookie 与 CSRF 边界见 [第 11 篇](11-M4-M5实施合同.md) 和 [第 12 篇](12-M4-M5使用与验收.md)。

这不表示放弃基本数据和 Git 保护：CLI 仍需防止事务部分提交、并发覆盖、路径误用和误删 dirty Worktree。

## 2. SQLite 保护

- Task、Session、Checkpoint、Note 和 History 只通过 Application Service 写入；
- AI、Hook 和 GUI 不得直接执行数据库 mutation；
- 每个连接启用 `foreign_keys`、WAL 和有限 `busy_timeout`；
- 除 `task create` 外，每次面向已有 Task 的 mutation 接收调用方最近读取的 expected version，使用短时 SQLite 写事务和 compare-and-swap；
- 业务变更和对应 History 必须同事务提交，任一步失败都整体回滚；
- 普通数据库 mutation 不另外维护跨进程锁文件，进程间写入由 SQLite 和乐观 version 共同协调；Worktree 外部 mutation 例外使用不承载业务状态的按 Task OS advisory lock；
- 不在数据库写事务中执行 Git 或 AI 客户端长操作；
- 数据库繁忙、version 不匹配或约束冲突时返回明确错误，不覆盖新版本；
- 只对空数据库执行单一 Schema 的原子初始化；`PRAGMA user_version=4` 标识当前开发格式。普通连接只读版本，写事务在取得写锁后复核；不迁移、不自动重建旧数据库。
- 数据库损坏或初始化失败时不得自动删除、重建或覆盖用户数据库。

Project/组件/源码关联的独立 revision/History、任务归属及组件范围 CAS 见 [项目合同](16-项目与上下文复用.md)。项目名、目录归属或共享事实不构成执行授权；项目元数据修改不自动 claim、adopt 或改变 Task version。Git 源码路径按所选 Worktree 实时解析，观察到目录原生身份变化、越界或跨仓库时拒绝；SourceRoot 删除只解除元数据关联，不删除文件。Schema 2 活动库仍需独立显式迁移方案，禁止直接切换开发构建。

## 3. Claim 与接管

`task claim` 不是权限授权，只是记录当前处理该 Task 的 Session。

- 没有当前 Session 时，使用尚不存在的 Session ID 创建未结束 Session 并领取；
- 相同且尚未结束的当前 Session、调用方携带当前 Task version 时返回同状态 no-op success，不写 History、不递增 version；携带旧 version 原样重试时返回冲突；
- 已结束、属于其他 Task 或已经承载其他继续关系的 Session 不能被重新激活为当前 Session；
- 已有其他当前 Session 时返回冲突和提示；
- 用户使用 `--take-over` 和尚不存在的新 Session ID 可以明确接管；
- 接管动作追加到 History，新 Session 的 `continuedFrom` 指向旧 Session，旧 Session 保留且不伪造 `endedAt`；
- `resume` 的目标 Session ID 必须尚不存在且不同于来源；Task 存在活跃当前 Session 时要求 `--take-over`；
- `session close` 关闭当前 Session 时必须在同一事务中清空 Task 引用，但不自动关闭 Task。

初版不使用自动超时或心跳回收；Session 接管只由用户明确触发。

## 4. Worktree 最低保护

默认禁止：

- `reset --hard`；
- `clean`；
- force checkout/switch；
- 隐式 stash；
- 未请求的 `git add -A`；
- Git push；
- dirty Worktree 强制删除。

`worktree remove` 必须先实时读取状态。存在 staged、unstaged、untracked 或 ignored 文件时拒绝删除；ignored 文件同样可能是唯一副本，不能因 Git 默认状态输出省略它们而视为 clean。由用户先自行提交、复制、生成补丁或清理。

`create/remove/adopt/detach` 必须先取得跨进程 OS advisory lock，再重新读取 expected version、数据库引用和现场前置条件，并持有锁直到 Git 后置观察及数据库结果确定。锁文件位于用户应用数据目录的 `agent-steward/locks`，名称为 `SHA-256(canonicalDatabasePath + NUL + 数字 taskId)`，目录使用 Unix `0700` 或当前用户专属 Windows DACL。锁只提供进程存活期间的互斥，不保存“操作进行中”等业务事实；崩溃后由操作系统释放。锁冲突返回 `WORKTREE_OPERATION_BUSY`，不能等待期间持有 SQLite 写事务。V0 的数据库本就不支持跨 OS 用户共享，因此该用户级锁不承担多用户协调。

初版不持久化复杂的 Operation Plan。Git 操作与 SQLite 事务不能形成单一原子事务；Git 一旦启动，无论退出状态如何都必须重新观察现场。如果 Git 已改变现场，或启动后无法证明现场未改变而数据库尚未提交，命令必须以 `PARTIAL_EXTERNAL_STATE` 报告真实或 `unknown` 现场、数据库引用状态和显式恢复命令，不能自动执行破坏性补偿，也不能伪装成普通 Git 失败。只有现场证明未改变时，非零退出才返回 `GIT_COMMAND_FAILED`。`worktree adopt` 只登记已经由 Git 证明存在的 Worktree；`worktree detach` 只清除已经由 Git 和文件系统证明不存在、且期望路径匹配的陈旧引用；两者均不得修改文件。

## 5. 路径与 Repository 身份

所有会影响 Worktree 或数据库引用的路径先转换为 `CanonicalPath`，不能比较未经解析的用户输入字符串：

1. 相对路径在解析命令时立即相对于调用进程当前目录转为绝对路径；
2. 已存在路径通过操作系统文件系统解析 symlink、别名和 `.`/`..`，并在本次操作内记录可用的文件对象身份；
3. 尚不存在的 Worktree 目标路径从最近的已存在祖先开始规范化，再逐段附加剩余普通组件；剩余组件不得是空、`.` 或 `..`；
4. Git Repository 身份使用 `git rev-parse --git-common-dir` 的结果；相对输出先相对于 Git 工作目录展开，再规范化为绝对 common-dir。Worktree 成员关系使用 `git worktree list --porcelain -z` 观察，不能只比较 `--repo` 展示路径；
5. 数据库中的 `repository_path` 和 `worktree_path` 保存规范化绝对路径；用户原始输入只用于本次诊断，不成为身份依据；
6. 路径先从最近已存在祖先规范化；规范化目标完全相同时直接判等，两条路径都存在时比较文件对象身份。缺失路径只接受规范化后的精确拼写，不探测或模拟大小写及 Unicode 比较规则，也不持久化路径比较键。`create/adopt` 在写事务内扫描现有引用，确保同一实际 Worktree 只有一个 Task；中文路径可以创建、采纳和清理。
7. Git 操作前立即重新观察目标、父目录和 Repository 身份；此时无法证明身份稳定时返回 `PATH_IDENTITY_UNKNOWN`，不得启动 Git。Git 一旦启动，无论退出状态如何都再次规范化并观察真实路径；如果无法证明现场未改变，返回 `PARTIAL_EXTERNAL_STATE`，其中 `gitState="unknown"` 并建议运行 `taskctl doctor`，不能返回暗示现场未改变的普通错误。

Linux 在身份快照存活期间持有 `O_PATH | O_CLOEXEC` 文件描述符，并从同一描述符读取 `dev/ino`，防止原对象删除后 inode 被回收复用。克隆快照共享句柄，最后一个快照释放时自动关闭；不读取文件内容，不要求对象读取权限，也不把句柄传给 Git 子进程。该措施覆盖快照建立到复核之间的 inode 复用，不将路径复核与后续外部 Git 操作变成原子事务。

#34 将活跃 `ExistingPathIdentity` 与可序列化 `ExistingPathIdentityRecord` 分开；活跃身份不能从 JSON 反序列化，序列化只投影原来的 canonical_path/dev/ino（Windows 原生对象 ID 对）记录，不保存句柄。记录重新匹配只产生新的现场观察，不能证明旧进程结束后的身份连续性。项目文件/宿主规则双次观察期间保留首轮身份；持久记录到新观察之前的间隔不受 pin 保护，`PERSISTED_IDENTITY_CONTINUITY_UNPROVEN` 不解除。

`record_path` 不是 Git 安全身份。存在时保存规范化绝对路径；不存在时只保存相对于调用时当前目录展开后的绝对弱引用，并在查询时返回 `RECORD_PATH_MISSING` 警告。

## 6. Session 与隐私

- SQLite 数据库文件默认不提供内容级加密，因此 Task、Checkpoint 和导入内容不得保存 Token、Cookie、密码或授权请求头；
- 数据库放在当前用户的应用数据目录，不得主动放入共享目录或 Git 仓库；Unix 应用目录使用 `0700`，数据库及 WAL/SHM 不得放宽于 `0600`，Windows 使用当前用户专属 DACL；AppContainer 只可额外使用 token 明确给出的包 SID，restricted token 只可原样保留目标对象已有、父目录 ACL 独立确认由宿主授予且与当前 token 非广泛 restricted SID 匹配的 ACE，不得根据候选数量或账户名称推断隔离 SID，也不得允许 Everyone、其它广泛主体或 capability SID；每次命令都必须同时检查父目录与已存在的数据库、`-wal`、`-shm` 文件本身，无法证明默认或自定义数据库目录、数据库文件或附属文件满足权限要求时必须返回 `INSECURE_DATABASE_PERMISSIONS`；命令在打开数据库之前失败时（如缺少敏感内容确认）也必须执行该检查，不能因为未打开数据库就跳过已有文件的权限验证；
- 初版优先保存 Session ID 和记录路径，不复制完整聊天；
- 用户明确导入 Session 文件时必须先检查敏感内容并携带显式确认；确认缺失时在文件读取和 SQLite mutation 前拒绝；导入副本保存在 SQLite 中，只接受不超过 16 MiB 的普通文件并以固定大小缓冲区有界流式计算哈希；
- Session Import 必须支持元数据查询和显式删除；删除后内容不得再由任何 V0 Query 返回；
- 不记录或推断模型隐藏 Chain of Thought；
- Session 摘要和 Checkpoint 不能自动改变 Task 状态；
- 当前 Hook 在落盘前投影元数据并丢弃正文，只采集客户端实际提供的事件。

`session import remove` 提供逻辑删除，不承诺 SSD、文件系统快照或既有外部备份上的取证级物理擦除。删除连接必须在删除前启用 SQLite `secure_delete=ON`；提交后尝试 `wal_checkpoint(TRUNCATE)`。如果 checkpoint 因并发读取而未完成，逻辑删除仍成功，但返回 `PHYSICAL_ERASURE_NOT_GUARANTEED` 警告。History 只记录 Import ID、Session ID、SHA-256 和删除时间，不能复制被删除内容。V0 不自动删除原始 `source_path` 文件。

## 7. 必须保持的不变量

- Task ID 由 `INTEGER PRIMARY KEY AUTOINCREMENT` 生成，保持不可变且删除后不复用；可选 `taskKey` 唯一，并且只可从 `NULL` 设置一次；`taskKey` 按原文解析，不能为纯数字或以 `#` 开头；
- Task 的 title、goal、scope 和 acceptance criteria 可以暂缺，但设置后不能清空，且 `completed` 关闭前必须全部完整；
- Task 的 `current_session_id` 必须引用属于同一 Task 的已登记 Session；
- Task 的当前 Session 必须尚未结束；
- `resume` 后旧 Session 记录必须保留，新旧 Session 必须属于同一 Task，并可通过 `continued_from` 和 History 查询；
- Session 的 `continued_from` 不得指向自身或形成环；
- Checkpoint 必须关联同一 Task 的来源 Session；
- 非 `blocked` Task 不得保留阻塞字段，非 `closed` Task 不得保留关闭字段；closed Task 不得保留当前 Session 或下一步；
- Task mutation 和对应 History 要么共同提交，要么共同回滚；
- Git 现场只能来自实时观察；
- Task 的 Repository 路径、common-dir 身份、Branch 和 Worktree 引用必须同时为空或同时存在，`worktree create` 不得覆盖已有引用；
- 同一规范化 Worktree 路径最多由一个 Task 登记；同一 Task 的 Worktree mutation 必须串行执行；
- 缺失的登记路径执行 `detach` 或由 `doctor` 复核时，Git 登记查询必须使用数据库登记路径规范化后的精确路径，不得依赖可能拒绝缺失 Unicode 分量的通用路径键，也不得用仅用于验证 `--expected-path` 的调用方别名代替；
- dirty Worktree 不能由 `taskctl` 强制删除；
- AI 不能仅凭摘要、测试文本或 Session 结束自动关闭 Task。
