# M4 / M5 使用与验收

本指南对应 V0 本地实现，与 V1 同名组件无继承关系。设计合同见 [11-M4-M5实施合同](11-M4-M5实施合同.md)。

## 安装与启动

```bash
cargo build --workspace --locked
# 可选：安装到 Cargo bin 目录（taskctl + task-hook，以及 taskd）
cargo install --path crates/cli --locked
cargo install --path crates/server --locked

# 使用新的隔离数据库启动本地工作台
cargo run -p steward-server --bin taskd -- --database /tmp/steward-m5-demo/steward.db
```

服务默认监听 `http://127.0.0.1:43123`，可以收藏这个固定地址；`--port <端口>` 可更改，`--port 0` 专用于临时端口。端口占用时启动失败，不静默换地址。显式 `--bind <本机IPv4>` 可改为指定网卡地址（不允许 `0.0.0.0`、广播或多播）；页面必须使用启动输出的精确 IP 和端口，Host/Origin 校验及凭据认证保持开启。非回环 HTTP 会暴露到该接口，凭据与任务数据不加密传输，仅在受控网络试运行；程序不会修改防火墙。终端显示页面 URL 和凭据文件路径，不显示凭据内容。默认启动后自动打开本机浏览器并连接，无需复制凭据；无桌面/自动化场景传 `--no-open`。自动连接使用仅在内存保存的随机一次性连接码，120 秒过期，通过 URL fragment 交给本机浏览器（不打印完整链接），页面立即清除 fragment，再用 `POST /api/connect` 兑换本机管理员的浏览器授权 Cookie，不向页面返回管理员凭据。兑换同样检查 Host/Origin，连接码仅可成功消费一次且不能直接调用业务接口。所有敏感接口仍要求凭据，不按本机 IP 放行。浏览器启动失败或链接失效时可手动连接；其他设备只分发终端显示的 `Read-only credential file` 内容。首次启动在私有 `runtime/identity` 目录生成管理员 `credential` 和只读 `readonly-credential`，后续启动复用，退出不删除。权限由凭据决定而非 IP；不要把管理员凭据分享给只读设备。首次授权后通过 30 天有效的 HttpOnly、SameSite=Strict Cookie 记住浏览器；普通网址、新标签页、刷新及同地址重启均可恢复，不在 JS 存储中保存长期凭据。禁用 Cookie 时无法记住或建立浏览器登录。退出登录会撤销本浏览器授权；管理员点击“撤销浏览器授权”可撤销当前地址全部浏览器授权（含自己），但不会轮换凭据文件。授权的哈希及角色保存在私有 identity/browser-sessions.db，最多 256 项；服务端校验过期时间和长期凭据绑定。如需撤销泄露的凭据，先停止所有使用该 runtime 目录的 taskd，明确删除对应的 identity 凭据文件，再启动生成新值；损坏或不安全的已有文件会被拒绝，不静默覆盖。切换端口会改变浏览器存储的 origin，自动连接仍可使用。

`--runtime-dir` 可指定现有私有目录或尚不存在的新目录。已有目录如果对其他用户开放会被拒绝，不会自动更改共享目录权限。GUI 静态 HTML/CSS/JavaScript 已嵌入二进制，无 Node、React、外部 CDN 或独立前端服务运行依赖。

**数据库格式：**本构建使用 SQLite `user_version=2`。旧 M1–M3 构建的 schema 1 数据库不会被迁移、删除或重建；必须指定新数据库。旧数据库请保留给原构建使用。HTTP/CLI 业务 envelope 的 `schemaVersion` 仍为 2，与数据库版本是不同概念。

## GUI 工作流

1. 创建最小任务，再编辑标题、目标、范围、验收条件和下一步。非空标题仍为 `MMDD｜类型｜主题`。
2. 点击“开始任务”创建执行 Session；已有任务通过“换会话继续”显式创建新的 Session，需要时确认接管。
3. 更新进展、记录决策/风险、阻塞或解除阻塞。切换前保存结构化 Checkpoint。
4. “会话”查看继续关系、Hook 观测和 Import 元数据。“代码现场”显示登记路径与实时 Git 观察，支持显式创建/删除/adopt/detach；dirty 删除仍被拒绝。
5. “复制交接上下文”重新读取快照，输出目标、验收、Checkpoint、Session 和 Git 状态。复制失败时可以手工复制文本。
6. 版本冲突保留编辑内容，展示最新任务，需手工确认采用该版本、审查内容后重新提交。请求中断显示结果未确认；刷新核对前不要重试，GUI 不自动重放写操作。
7. “关闭任务”必须选择结果并勾选确认。测试、消息、Hook closed 或 Session close 均不会自动关闭 Task。

## 通用 JSON Hook

首个适配器是 `task-hook`，面向能显式启动进程并提供 JSON stdin 的宿主。它是本项目定义的协议。Codex 与 pi 原生入口、绑定配置和事件映射见 [原生适配指南](../../integrations/README.md)。未配置 Hook 时手工 CLI 完整可用。

先显式创建/领取并绑定；以下操作只使用示例数据库：

```bash
taskctl --database /tmp/steward-hook-demo/steward.db --json task create DEMO
# 读取输出 version=1
taskctl --database /tmp/steward-hook-demo/steward.db --json task claim DEMO --session local-a --if-version 1
# 读取输出 version=2
taskctl --database /tmp/steward-hook-demo/steward.db --json session bind local-a --source generic --external-session host-a --if-version 2
```

宿主使用参数数组调用，不拼接 Shell；参数中的 Session 和外部 ID 必须来自明确绑定。stdin 为一个事件：

```json
{
  "eventId": "host-event-1",
  "kind": "idle",
  "occurredAt": "2026-09-07T00:00:00Z",
  "message": "这个额外字段会被适配器丢弃，不会存储"
}
```

```bash
task-hook --database /tmp/steward-hook-demo/steward.db \
  --session local-a --source generic --external-session host-a < host-event.json

taskctl --database /tmp/steward-hook-demo/steward.db --json hook list local-a --limit 100
```

- 宿主输入最多 256 KiB；只投影 eventId/kind/occurredAt，加上显式绑定参数组成最多 16 KiB 的标准事件。所有正文、工具参数/结果、自由格式错误、附件等额外字段均丢弃。
- 身份字段只能使用有界 ASCII 标识符，不能放凭据、文件内容或自由文本。来源、时间和事件种类均严格校验。
- 宿主必须提供稳定事件 ID；不能每次重试生成新 ID。相同 ID 不同元数据会冲突。
- busy 时适配器最多重试两次，间隔 100/200 ms；事件写事务使用 100 ms busy timeout。不会持久化重试队列，也不会吞掉失败状态。宿主应显示 stderr/非零退出但继续允许正常 CLI 工作。
- started/resumed/idle/closed 仅代表客户端报告；包括结束之后迟到的事件，都不改变执行生命周期。每个外部 ID 只绑定一个本地 Session，不能借事件跨 Task 改绑。
- 每 Session 上限 10,000 条（含删除后的去重标记）。满时停止接收新 ID并提示，不悄悄驱逐历史；重试已有 ID 仍可判重。需要新的执行会话和新的外部会话标识才能继续独立采集。
- 清除：先 `task show` 获取新版本，再显式执行 `hook clear local-a --if-version <v> --yes`。清除可见记录，保留 session/event ID 与指纹，防止重试复活；不承诺物理擦除，也不释放去重容量。

已有标准事件（包含 schemaVersion/sessionId/source/externalSessionId）可直接使用 `taskctl --json --input event.json hook ingest` 或经认证的 `POST /api/hook`。标准接收接口拒绝未知字段，不能直接把客户端原始消息交给它。

## HTTP 合同速查

API 支持 `X-Steward-Token`（脚本/CLI）或浏览器 Cookie；一次性码兑换 `POST /api/connect` 使用 `X-Steward-Connect`。手工首次登录使用请求头凭据调用 `POST /api/login` 建立 Cookie。`POST /api/logout` 撤销当前 Cookie，`POST /api/browser-sessions/revoke` 仅管理员可用。带 Cookie 的写请求要求精确 Origin、`X-Steward-CSRF: 1`；POST 还要求 `Content-Type: application/json`。`GET /api/access` 返回 `admin` 或 `reader`。除首次浏览器授权和退出登录外，只读凭据仅允许 GET/HEAD，对所有业务写接口（包括 Hook/Import/Worktree）返回 403 `READ_ONLY`，隐藏按钮仅是 UI 辅助，不代替后端授权。

页面通过带认证头的 fetch SSE 连接 `GET /api/events` 自动刷新；重连后重新取快照，不重放写请求。服务每秒检查只读连接的 SQLite `data_version`，因此 CLI/Hook 的提交也可触发通知；不持有数据库事务，不推送业务内容，每实例最多 16 条订阅且不占普通 API 工作槽位。正在填写的表单保留内容，关闭后再刷新；仍保留手动刷新。尚未提交到 SQLite 的外部 Git 文件变化不触发通知，查看代码现场时仍需手动刷新。

GUI 与 API 同源；跨 Origin、null Origin、非精确 Host 和跨站 Fetch Metadata 均拒绝。不提供 CORS 放行。当前 HTTP 不支持 Secure Cookie；非回环 HTTP 仍有窃听风险，不能代替 HTTPS。

查询：

- `GET /api/tasks?view=active|in-progress|blocked|recent&query=...&pageSize=30&cursor=...`；也支持 status/taskKey/fields，view 与 status 互斥。
- `GET /api/tasks/:id`、`/context`、`/notes`、`/history`、`/worktree-status`。
- `GET /api/sessions?taskId=:id`、`/api/sessions/:id`、`/imports`、`/events?after=0&limit=100`。
- `GET /api/doctor`。

命令使用 `POST /api/commands/:command`，JSON 未知字段拒绝；Task `taskId` 为整数，`expectedVersion` 来自调用方已有快照，不允许服务现读现填。详细字段可直接查看 `crates/server/src/lib.rs` 的严格 `Command` enum。

```json
{"input":{"title":"0907｜功能｜示例任务","goal":"明确下一步"}}
```

上例提交到 `task-create`；下面例子提交到 `task-update`：

```json
{"taskId":1,"expectedVersion":2,"patch":{"nextStep":"补充验收条件"}}
```

命令涵盖 task-create/update/retitle/note/block/unblock/claim/resume/checkpoint/close、session-bind/attach/close/import-add/import-remove、hook-clear 和 worktree-create/adopt/remove/detach。关闭、删除、清除及 Worktree 写操作必须显式 `confirmed:true`；Import 要求 `confirmSensitiveContentReviewed:true`。HTTP 文件路径必须为绝对路径。

业务成功/失败 envelope：`schemaVersion, ok, data, warnings, error`。错误码沿用 CLI；另有 HOOK_EVENT_CONFLICT、HOOK_CAPACITY_REACHED、UNAUTHORIZED、REQUEST_ORIGIN_REJECTED、SERVER_BUSY。Hook 不递增 Task version，绑定和清除则递增；其他 Task mutation 保持原 CAS 合同。

服务不提供请求级幂等 Operation。HTTP 断连/超时不取消或回滚已经开始的业务操作；创建和 Git 写操作的结果必须重新查询确认。对 PARTIAL_EXTERNAL_STATE 展示结构化恢复建议，只能显式执行经过复核的 adopt/detach。

## 验证方法

```bash
node --test crates/server/tests/browser/connection.test.cjs
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo fmt --all -- --check
git diff --check
```

浏览器测试启动临时 Daemon、数据库和 Git 仓库，完成后清理；不会访问用户默认数据库。截图位于 `.local/m5-desktop.png` 和 `.local/m5-mobile.png`。GUI 开发改动后必须重新 `cargo build --workspace --locked`，因为资源在编译时嵌入。

本轮 `cargo test --workspace --locked` 共 77 项通过，Clippy/格式/diff 检查以及完整浏览器流程通过。

当前验证平台：macOS + Chrome。Windows/Linux 路径及 ACL 分支未在本轮执行，不能视为已经通过跨平台验收。Codex 与 pi 已补充原生入口及契约测试；真实客户端信任配置与模型运行未在本轮执行。消息正文/附件采集和实时订阅不属于当前交付。
