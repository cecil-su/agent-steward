# 架构与流程图

> 当前仓库处于设计阶段，尚无实现代码。实线表示初版范围，虚线表示后续规划。

## 1. 项目理解

`taskctl` 的初版目标是保存任务上下文，让 AI 在不同窗口和 Session 之间继续工作，并提供轻量 Worktree 命令。CLI 使用 Rust 实现；Task、Session、Checkpoint、Note 和 History 保存在本机 SQLite 数据库中；Worktree 现场以 Git 实时观察为准。

## 2. 架构图

```mermaid
flowchart TB
    subgraph Clients["初版入口"]
        Human["人类"]
        Creator["任务创建 AI 窗口"]
        Executor["任务执行 AI 窗口"]
    end

    CLI["Rust taskctl CLI<br/>人类输出 + JSON"]

    subgraph App["Application Service"]
        TaskService["Task Service<br/>create / claim / update / resume / close"]
        SessionService["Session Service<br/>attach / continue / checkpoint"]
        WorktreeService["Worktree Service<br/>create / status / remove"]
    end

    SQLiteAdapter["SQLite Repository<br/>migration / transaction"]
    SQLiteDB[("本机 SQLite<br/>Task / Session / Checkpoint<br/>Note / History")]
    GitAdapter["Git Adapter"]
    GitFS["Git / 文件系统"]

    Hook["AI Client Hook"]
    RuntimeAdapter["Runtime Adapter"]
    GUI["React Web GUI"]
    Daemon["Rust Local Daemon"]

    Human --> CLI
    Creator --> CLI
    Executor --> CLI
    CLI --> TaskService
    CLI --> SessionService
    CLI --> WorktreeService

    TaskService --> SQLiteAdapter
    SessionService --> SQLiteAdapter
    WorktreeService --> SQLiteAdapter
    SQLiteAdapter --> SQLiteDB
    WorktreeService --> GitAdapter
    GitAdapter --> GitFS

    Hook -. "后续：可观察 Session 数据" .-> RuntimeAdapter
    RuntimeAdapter -.-> SessionService
    GUI -.-> Daemon
    Daemon -.-> TaskService
    Daemon -.-> SessionService
    Daemon -.-> WorktreeService
```

SQLite 由 CLI 或后续本地 Daemon 直接访问，不需要独立数据库服务，不支持多台机器共享同一个数据库文件。

## 3. 创建、领取和跨会话继续流程

```mermaid
flowchart TD
    CreateWindow(["任务创建 AI 窗口"]) --> Create["task create<br/>事务写入 Task + History"]
    Create --> Open["Task 状态为 open"]

    ExecWindow(["执行窗口 / Session A"]) --> Claim["task claim"]
    Open --> Claim
    Claim --> Conflict{"已有其他当前 Session？"}
    Conflict -- "是" --> Choice{"用户明确 take-over？"}
    Choice -- "否" --> Stop(["回滚并返回冲突"])
    Choice -- "是" --> Bind
    Conflict -- "否" --> Bind["同一事务登记 Session A<br/>更新 Task + History"]

    Bind --> Worktree["可选：worktree create"]
    Worktree --> Work["AI 执行并主动调用<br/>task update / note / block"]
    Work --> Checkpoint["task checkpoint<br/>事务保存 Checkpoint、Task 引用和 History"]

    Checkpoint --> Continue{"需要新 Session 或新窗口？"}
    Continue -- "是" --> Resume["Session B 执行 task resume"]
    Resume --> Restore["事务登记 Session B 并保留 Session A<br/>读取最新 Checkpoint<br/>重新观察 Git 现场"]
    Restore --> Work
    Continue -- "否，任务完成" --> Close["task close<br/>事务保存关闭结果和 History"]
    Close --> End(["结束"])
```

## 4. AI 在会话中更新数据

```mermaid
sequenceDiagram
    autonumber
    actor AI as AI Session
    participant CLI as Rust taskctl CLI
    participant App as Application Service
    participant DB as SQLite Repository
    participant Git as Git / 文件系统

    AI->>CLI: task show / claim / resume --json
    CLI->>App: 结构化 Query 或 Command
    App->>DB: 事务读取或更新 Task / Session / Checkpoint
    DB-->>App: 一致数据库结果
    App->>Git: 写事务外实时观察 Worktree
    Git-->>App: HEAD / dirty / staged / untracked
    App-->>AI: Task + Checkpoint + Git + nextStep

    AI->>CLI: task update / note / block
    CLI->>App: 显式 Task mutation
    App->>DB: BEGIN IMMEDIATE + version 校验
    App->>DB: 原子写入业务变更 + History
    DB-->>App: COMMIT 或完整 ROLLBACK
    App-->>AI: 更新后的结构化结果

    AI->>CLI: task checkpoint --input checkpoint.json
    CLI->>App: 保存恢复上下文
    App->>Git: 写事务外读取当前 HEAD
    App->>DB: 事务写入 Checkpoint + Task 引用 + History
    DB-->>App: COMMIT 或完整 ROLLBACK
    App-->>AI: Checkpoint 已保存
```

## 5. 轻量 Worktree 流程

```mermaid
flowchart TD
    Request(["worktree create"]) --> Validate["检查数据库 Task 引用、Repository、Branch 和目标路径"]
    Validate --> Add["执行 git worktree add"]
    Add --> Added{"Git 返回成功？"}
    Added -- "否" --> Error(["返回 Git 错误，不更新数据库"])
    Added -- "是" --> Save["事务保存 Worktree 引用和 History"]
    Save --> Saved{"数据库提交成功？"}
    Saved -- "否" --> PartialCreate["报告已创建的真实路径和修复方式<br/>不自动破坏性补偿"]

    Saved -- "是" --> Status["worktree status<br/>实时读取 HEAD 与文件状态"]
    Status --> Remove(["worktree remove --yes"])
    Remove --> Dirty{"存在 staged、unstaged<br/>或 untracked 文件？"}
    Dirty -- "是" --> Refuse(["拒绝删除，由用户处理现场"])
    Dirty -- "否" --> GitRemove["执行 git worktree remove"]
    GitRemove --> Removed{"Git 返回成功？"}
    Removed -- "否" --> Keep(["保留数据库引用并返回错误"])
    Removed -- "是" --> Clear["事务清除 Worktree 引用并写入 History"]
    Clear --> Cleared{"数据库提交成功？"}
    Cleared -- "否" --> PartialRemove["报告陈旧数据库引用和修复方式"]
    Cleared -- "是" --> Done(["删除完成"])
```

SQLite 事务不能与 Git 子进程构成同一原子事务。任何部分完成都必须如实返回，不得自动 force、clean、reset、stash 或删除用户现场。

## 6. Hook / Runtime Adapter 后续流程

```mermaid
flowchart LR
    Client["AI Client"] -.-> Hook["Client Hook"]
    Hook -.-> Adapter["Runtime Adapter<br/>统一、脱敏、幂等"]
    Adapter -.-> SessionService["Session Service"]
    SessionService -.-> SQLiteSession["SQLite Session / Observable Log"]

    Explicit["AI 显式调用 taskctl"] --> TaskService["Task Service"]
    TaskService --> SQLiteTask["SQLite Task / Checkpoint / History"]

    Guard["Hook 只补充可观察 Session 数据<br/>不能自动更新或关闭 Task"] -.-> SessionService
```
