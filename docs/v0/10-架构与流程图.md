# 架构与流程图

> 当前仓库已包含 V0 `taskctl` 参考实现。图中 CLI 为 M1–M3，Hook 与 Daemon/GUI 为 V0 M4/M5，不代表 V1 或未来 V2；不同版本方案不存在默认继承、替代或升级关系。

## 1. 项目理解

`taskctl` 的初版目标是保存任务上下文，让 AI 在不同窗口和 Session 之间继续工作，并提供轻量 Worktree 命令。CLI 使用 Rust 实现；Task、Session、Checkpoint、Note 和 History 保存在本机 SQLite 数据库中；Worktree 现场以 Git 实时观察为准。

## 2. 架构图

```mermaid
flowchart TB
    subgraph Clients["初版入口"]
        Human["人类"]
        Creator["任务创建 AI 窗口"]
        Executor["任务执行 AI 窗口"]
    end

    CLI["Rust taskctl CLI<br/>人类输出 + JSON"]

    subgraph App["Application Service"]
        TaskService["Task Service<br/>create / claim / update / resume / close"]
        SessionService["Session Service<br/>attach / continue / checkpoint"]
        WorktreeService["Worktree Service<br/>create / status / remove<br/>adopt / detach"]
    end

    SQLiteAdapter["SQLite Repository<br/>initialization / transaction"]
    SQLiteDB[("本机 SQLite<br/>Task / Session / Checkpoint<br/>Note / History / Session Import")]
    GitAdapter["Git Adapter"]
    GitFS["Git / 文件系统"]

    Hook["AI Client Hook"]
    RuntimeAdapter["Runtime Adapter"]
    GUI["内嵌静态 Web GUI"]
    Daemon["Rust Local Daemon<br/>loopback + auth + Origin/CSRF"]

    Human --> CLI
    Creator --> CLI
    Executor --> CLI
    CLI --> TaskService
    CLI --> SessionService
    CLI --> WorktreeService

    TaskService --> SQLiteAdapter
    SessionService --> SQLiteAdapter
    WorktreeService --> SQLiteAdapter
    SQLiteAdapter --> SQLiteDB
    WorktreeService --> GitAdapter
    GitAdapter --> GitFS

    Hook -->|仅事件元数据| RuntimeAdapter
    RuntimeAdapter --> SessionService
    GUI --> Daemon
    Daemon --> TaskService
    Daemon --> SessionService
    Daemon --> WorktreeService
```

SQLite 由 CLI 或后续本地 Daemon 直接访问，不需要独立数据库服务，不支持多台机器共享同一个数据库文件。

## 3. 创建、领取和跨会话继续流程

```mermaid
flowchart TD
    CreateWindow(["任务创建 AI 窗口"]) --> Create["task create [taskKey] [--input]<br/>生成数字 ID，可最小创建或校验完整 JSON<br/>事务写入 Task + History"]
    Create --> Open["Task 状态为 open"]

    ExecWindow(["执行窗口 / Session A"]) --> Read["task show --json<br/>读取 Task version"]
    Read --> Claim["task claim 12 / #12 / taskKey<br/>--if-version"]
    Open --> Claim
    Claim --> Conflict{"已有其他当前 Session？"}
    Conflict -- "是" --> Choice{"用户明确 take-over？"}
    Choice -- "否" --> Stop(["回滚并返回冲突"])
    Choice -- "是" --> Bind
    Conflict -- "否" --> Bind["同一事务登记 Session A<br/>更新 Task + History"]

    Bind --> Worktree["可选：worktree create"]
    Worktree --> Work["AI 执行并携带最新 version<br/>task update / retitle / note / block / unblock"]
    Work --> Checkpoint["task checkpoint --if-version<br/>事务保存 Checkpoint、Task 引用和 History"]

    Checkpoint --> Continue{"需要新 Session 或新窗口？"}
    Continue -- "是" --> Resume["Session B 使用尚不存在的新 ID 执行 task resume<br/>--from-session + --if-version<br/>存在活跃当前 Session 时要求 --take-over"]
    Resume --> Restore["事务登记 Session B 并保留 Session A<br/>读取最新 Checkpoint<br/>重新观察 Git 现场"]
    Restore --> Work
    Continue -- "否，任务完成" --> Close["task close --if-version<br/>事务结束当前 Session<br/>保存关闭结果和 History"]
    Close --> End(["结束"])
```

## 4. AI 在会话中更新数据

```mermaid
sequenceDiagram
    autonumber
    actor AI as AI Session
    participant CLI as Rust taskctl CLI
    participant App as Application Service
    participant DB as SQLite Repository
    participant Git as Git / 文件系统

    AI->>CLI: task show --json
    CLI->>App: 结构化 Query
    App->>DB: 只读事务读取 Task
    DB-->>App: Task snapshot
    App-->>AI: Task + version
    AI->>CLI: task claim / resume --if-version --json
    CLI->>App: 结构化 Command
    App->>DB: version CAS 更新 Task / Session / History
    DB-->>App: 一致数据库结果
    App->>Git: 写事务外实时观察 Worktree
    Git-->>App: HEAD / dirty / staged / untracked
    App-->>AI: Task + Checkpoint + Git + nextStep

    AI->>CLI: task update / retitle / note / block --if-version
    CLI->>App: 显式 Task mutation
    App->>DB: BEGIN IMMEDIATE + 请求 expected version CAS
    App->>DB: 原子写入业务变更 + History
    DB-->>App: COMMIT 或完整 ROLLBACK
    App-->>AI: 更新后的结构化结果

    AI->>CLI: task checkpoint --if-version --input checkpoint.json
    CLI->>App: 保存恢复上下文
    App->>Git: 写事务外读取当前 HEAD
    App->>DB: 事务写入 Checkpoint + Task 引用 + History
    DB-->>App: COMMIT 或完整 ROLLBACK
    App-->>AI: Checkpoint 已保存
```

## 5. 轻量 Worktree 流程

```mermaid
flowchart TD
    Request(["worktree create --if-version"]) --> Lock["取得按 Task 的 OS advisory lock<br/>锁冲突返回 WORKTREE_OPERATION_BUSY"]
    Lock --> Validate["CanonicalPath + Git common-dir<br/>重新检查 Task version、已存在 Branch、引用全部为空<br/>并复核目标父目录身份"]
    Validate --> Add["执行 git worktree add"]
    Add --> Reobserve["无论 Git 退出状态如何<br/>再次观察 CanonicalPath、RepositoryIdentity<br/>和 Worktree 登记"]
    Reobserve --> Created{"能证明目标 Worktree<br/>已正确创建？"}
    Created -- "否" --> CreateUnchanged{"能证明现场未改变？"}
    CreateUnchanged -- "是" --> CreateFailed(["GIT_COMMAND_FAILED<br/>不更新数据库"])
    CreateUnchanged -- "否" --> CreateUnknown(["PARTIAL_EXTERNAL_STATE<br/>gitState=unknown<br/>建议 taskctl doctor"])
    Created -- "是" --> Save["事务保存 Repository 路径、common-dir 身份<br/>Branch、Worktree 引用和 History"]
    Save --> Saved{"数据库提交成功？"}
    Saved -- "否" --> PartialCreate["PARTIAL_EXTERNAL_STATE<br/>报告真实路径与 adopt 命令<br/>不自动破坏性补偿"]
    PartialCreate --> Adopt["用户确认后 worktree adopt<br/>重新取得 Task lock<br/>观察 Git + version CAS"]
    Adopt --> Status

    Saved -- "是" --> Status["worktree status<br/>实时读取 HEAD 与文件状态"]
    Status --> RemoveLock["remove 重新取得按 Task advisory lock"]
    RemoveLock --> Remove(["worktree remove --if-version --yes"])
    Remove --> Dirty{"存在 staged、unstaged、untracked<br/>或 ignored 文件？"}
    Dirty -- "是" --> Refuse(["拒绝删除，由用户处理现场"])
    Dirty -- "否" --> GitRemove["执行 git worktree remove"]
    GitRemove --> RemoveObserve["无论 Git 退出状态如何<br/>重新观察路径和 Worktree 登记"]
    RemoveObserve --> Removed{"能证明 Worktree<br/>已正确移除？"}
    Removed -- "否" --> RemoveUnchanged{"能证明现场未改变？"}
    RemoveUnchanged -- "是" --> Keep(["GIT_COMMAND_FAILED<br/>保留数据库引用"])
    RemoveUnchanged -- "否" --> RemoveUnknown(["PARTIAL_EXTERNAL_STATE<br/>gitState=unknown<br/>建议 taskctl doctor"])
    Removed -- "是" --> Clear["事务清除 Worktree 引用并写入 History"]
    Clear --> Cleared{"数据库提交成功？"}
    Cleared -- "否" --> PartialRemove["PARTIAL_EXTERNAL_STATE<br/>报告陈旧引用与 detach 命令"]
    PartialRemove --> Detach["用户确认后 worktree detach<br/>重新取得 Task lock<br/>验证期望路径已不存在 + version CAS"]
    Detach --> Done
    Cleared -- "是" --> Done(["删除完成"])
```

SQLite 事务不能与 Git 子进程构成同一原子事务。任何部分完成都必须如实返回，不得自动 force、clean、reset、stash 或删除用户现场。

## 6. Hook / Runtime Adapter 后续流程

```mermaid
flowchart LR
    Client["AI Client"] --> Hook["Client Hook"]

    SessionService --> SQLiteSession["SQLite Session / Observable Log"]

```
