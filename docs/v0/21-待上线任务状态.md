# 待上线任务状态

## 语义与转换

`pending_release`（待上线）表示功能开发完成、尚未上线。它是未关闭状态，不代表上线、验收通过或业务完成，不增加强制验收门槛。

| 当前状态 | 命令 | 下一状态 |
| --- | --- | --- |
| `in_progress` | `task pending-release` | `pending_release` |
| `pending_release` | `task continue` | `in_progress` |
| `pending_release` | 用户明确选择`task close --outcome ...` | `closed` |

进入和返回只修改status、version、updatedAt；保留nextStep、当前Session、Checkpoint、项目及Worktree。非法来源、重复转换及过期CAS拒绝。需要阻塞时先显式返回进行中，再执行block。

关闭必须由用户明确选择。待上线支持四种关闭结果；completed要求title/goal/scope/acceptanceCriteria完整，其余结果要求reason。关闭同事务结束当前Session、清空当前关联、nextStep和阻塞字段。不要求所有任务经过待上线。

## CLI / HTTP

TASK/VERSION来自明确指定的隔离库，不能直接套用正式任务。

```bash
taskctl --database /absolute/test.db --json task pending-release TASK --if-version VERSION
taskctl --database /absolute/test.db --json task continue TASK --if-version VERSION
taskctl --database /absolute/test.db --json task list --view pending-release
taskctl --database /absolute/test.db --json task list --status pending_release
```

HTTP命令为`POST /api/commands/task-pending-release`、`POST /api/commands/task-continue`，请求字段为：

```json
{"taskId": 1, "expectedVersion": 2}
```

沿用admin/reader、Origin、CSRF和UI合同检查。查询支持`GET /api/tasks?view=pending-release`或`?status=pending_release`。JSON envelope为2，Web无业务写入口。

CLI关闭使用显式close合同；HTTP关闭要求confirmed:true。确认字段不能代替用户的实际关闭决定。

## 连续性与审计

- 待上线支持note、checkpoint、claim同Session no-op、显式take-over和resume；后两者保持待上线状态。
- checkpoint要求尚未结束的当前Session；currentSessionId为空时claim拒绝，须从明确来源resume，不重新激活已结束Session。
- update/project/components/retitle遵循[信息维护合同](20-任务信息维护.md)，不得借update修改status或执行字段。
- 转换在同一写事务中校验来源、执行CAS、递增version并写History，失败全部回滚。
- History类型为task.pending_release/task.continued，payload为previousStatus/status，sessionId为原当前Session或null；不改写已保存记录。

## 展示与存储

React列表/详情和项目关联任务显示紫色待上线标识，提供独立筛选。待上线归入未关闭/最近全部，不归入进行中/已关闭。没有独立统计API或仪表盘。

当前数据库Schema7包含该状态；普通连接只初始化空库或打开当前格式，不推断或批量修改任务状态。可导入的源格式及隔离步骤见[Schema7隔离导入](18-Schema7隔离导入与验证.md)。

UI API合同4、包格式1。外置包和页面请求必须匹配当前合同，不能只改manifest数字冒充兼容。内嵌资源来自crates/server/web-readonly。Windows启动器只接受Schema7，普通更新不跨Schema；正式部署/迁移与服务停启须独立确认。

## 验证入口与限制

- `cargo test --workspace --locked`：状态转换、关闭、CAS、Session/Checkpoint、维护、筛选及复制回滚。
- `web/`内`npm run typecheck`、`npm test`；获准的隔离环境可运行`scripts/browser-smoke.mjs`。
- `distribution/windows/test.ps1`、`test-local.ps1`、`test-ui.ps1`：包/Schema/UI合同及切换边界。

所有功能测试使用合成隔离数据。目标实例、跨平台、浏览器及人工业务验收须分别验证；不提供数据库降级或新写入反向合并保证。
