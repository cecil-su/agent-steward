# 测试与验收

## 1. 单元测试

- Task 状态转换矩阵、非法转换、关闭结果和字段清理；
- `claim` 的首次领取、当前 version 同状态 no-op、旧 version 原样重试冲突和接管提示；
- `claim` 拒绝重新激活已结束、属于其他 Task 或已承载其他继续关系的 Session；take-over 要求尚不存在的新 Session ID；
- `--take-over` 后 Session 历史正确；
- Checkpoint Schema 和 Task/Session 引用；
- Checkpoint 拒绝非当前、已结束或跨 Task Session，并拒绝 open/closed Task；
- `resume` 更新当前 Session 并保留 `continuedFrom`；
- `resume` 的来源解析、跨 Task 拒绝和活跃 Session take-over 要求；
- `resume` 拒绝目标等于来源、目标 ID 已存在或已结束，并保证新 Session 在同一事务中创建；
- `continuedFrom` 的 self-reference 和循环引用拒绝；
- Task 当前 Session 的 `endedAt` 必须为空；
- `session close` 原子清理当前引用但不改变 Task 状态；
- History sequence 单调递增；
- Task 最小创建、完整 JSON 创建、初始可空描述、描述设置后不可清空和 completed 前完整性门槛；新 title 的 `MMDD｜类型｜主题` 校验及 closed Task CAS retitle 不改变关闭状态；
- 数字、`#数字`、`taskKey` 三种引用跨 Task/Session/Checkpoint/History/Worktree 生效；`key:` 没有转义语义；
- 单次多字段 Merge Patch 只递增一次 version、写一条 History，`taskKey` 只可设置一次；
- Task Create 的可选 nextStep、Patch、Checkpoint、CLI DTO、Schema 和错误码；
- 每种真实 mutation 的 History change type 和最低 payload 完整，同状态 no-op 不产生 History；
- 输入未知字段、空 Patch 和必填空字符串全部拒绝。

## 2. SQLite 集成测试

所有测试使用独立临时数据库，不能访问用户默认数据库。

- 空数据库在单一事务中初始化；并发首次启动只能初始化一次；
- 不兼容或未标记的非空数据库被拒绝，已有内容不被转换或删除；
- Task AUTOINCREMENT ID 删除后不复用，ID 与已设置 taskKey 不可修改；
- 默认应用目录、数据库和 WAL/SHM 使用当前用户专属权限；默认或自定义路径无法证明安全时返回稳定警告；
- 重复启动不重复初始化；已有写事务时只读查询仍能读取已提交快照；
- 数据库版本与程序支持版本不匹配时拒绝写入；
- 每个连接启用外键，非法 Task/Session/Checkpoint 引用无法提交；
- current Session、continuedFrom、Checkpoint 和 Note/History 的跨 Task 复合引用无法提交；
- blocked/closed 字段组合违反行级约束时无法提交；
- 两个进程同时更新同一 Task 时不静默覆盖；
- 调用方携带旧 expected version 时，即使写事务开始后读到新数据也必须返回 `VERSION_CONFLICT`；
- busy timeout、version 冲突和约束冲突返回明确错误；
- mutation 任一步失败时 Task、Checkpoint 和 History 全部回滚；
- Checkpoint 写入后 Task 的最新引用一致；
- History sequence 在并发写入后仍唯一且单调递增；
- `session import add` 副本、哈希、Session source 和 Session 引用一致；
- `session import add` 在文件读取和 mutation 前拒绝缺少敏感内容确认的请求，拒绝跨 Task Session、超过 16 MiB 的文件和非普通文件，并使用固定大小缓冲区在有界读取时计算哈希；
- 相同 `sessionId + sha256` 返回现有元数据、不复制 BLOB、不写 History、不递增 version；
- `session import list` 不返回 BLOB；`session import remove` 删除后所有 Query 不再返回该 Import；
- Import 删除连接启用 `secure_delete=ON`，History 不含原文；WAL checkpoint 未完成时返回 `PHYSICAL_ERASURE_NOT_GUARANTEED`；
- Session 记录路径不存在时返回警告而不是伪造内容；
- `foreign_key_check` 和 `quick_check` 在正常数据库上通过；
- 初始化失败或遇到不兼容数据库时，不删除、重建或覆盖原数据库。

## 3. CLI 合同测试

- 人类输出可读；
- `--json` 固定包含 schemaVersion、ok、data、warnings 和 error，失败及可选字段不因空值而省略；
- 每个成功 Task mutation 返回完整 Task 和新 version；版本冲突返回 expected/current version；
- `--input <file>` 保持文件输入；`--json --input -` 从 stdin 读取原始字节并严格验证 UTF-8；输入不成为主存储；
- stdin 空输入、非法 UTF-8、非法 JSON 和未知字段稳定返回带 `field/reason` 的 `INVALID_INPUT`，不得 panic；
- JSON `schemaVersion: 2` 使用整数 Task `id/taskId`；人类输出使用 `#id`；
- Task list 的 status/taskKey/query 组合筛选、1–200 pageSize、游标续页与筛选摘要绑定、字段白名单投影均有合同测试；超长合法 query 不扩大 cursor，第一页返回的 cursor 可继续读取第二页；
- Task list 人类模式默认表格可读，单字段 `--format lines` 每条记录只占一行且不输出 ANSI 控制字符；
- 输入未知字段拒绝，输出新增字段可被消费者按 schemaVersion 判断；
- 每个稳定错误码的 exit code、retryable 和最低 details 与合同一致；
- `session list` 和 `task resume` 的 Session 数组固定按 `startedAt ASC, id ASC`；
- `--database` 可以隔离指定数据库，默认路径解析正确；
- 退出码正确；
- 非交互环境不弹隐式 Prompt；
- AI 可以只使用 JSON 输入输出完成创建、领取、Checkpoint 和恢复。

## 4. Worktree 测试

使用临时 Git 仓库验证：

- 使用已经存在的本地 Branch 创建 Worktree，分支不存在或已被占用时拒绝；
- Task 已有任一 Repository/Worktree 引用时，重复 create 在 Git 调用前返回 `WORKTREE_SAFETY_REFUSED`，既有引用和现场不变；
- 两个进程同时对同一 Task 执行 Worktree mutation 时只有持锁者可以进入 Git 阶段，另一方返回可重试的 `WORKTREE_OPERATION_BUSY`；进程崩溃后 OS lock 可重新取得；
- 相对路径、symlink、`.`/`..` 和操作系统路径别名规范化正确；中文 Worktree 可以创建，真实路径别名不能绕过唯一 Owner 检查；缺失路径要求精确拼写，外部删除后 `doctor` 可推荐且 `detach` 可执行清理；
- RepositoryIdentity 来自规范化 Git common-dir，两个 Worktree 不会被误判为不同 Repository；
- 创建或 adopt 成功后 `TaskView.repositoryCommonDir` 与数据库 `repository_common_dir` 一致；四个 Repository/Worktree 引用任意半登记组合都必须被行级约束拒绝；
- 两个 Task 不能登记同一规范化 Worktree 路径；
- 不存在的目标路径从最近已存在祖先规范化，父目录身份在 Git 操作前变化时拒绝；
- 状态命令准确报告 HEAD、dirty、staged、untracked 和 ignored；
- 登记 Worktree 已从文件系统消失时，`WorktreeStatus` 保留数据库路径和 Branch，返回 `registered=true`、`exists=false`，观察字段为 `null`；
- Git 创建后发生 Task CAS 冲突时，不写创建 History；释放事务后返回携带当前 version 且能成功执行的 adopt 建议；
- clean Worktree 可以在确认后删除；
- dirty Worktree 拒绝删除；只有 ignored 文件的 Worktree 也必须拒绝删除并保留文件；
- Git 命令使用参数数组，不拼接 Shell；
- 不执行 force、clean、reset、stash 或 push；
- 删除失败时不清除数据库中的 Worktree 引用；
- remove/detach 成功时 Repository 路径、common-dir 身份、Branch 和 Worktree 引用一起清空；
- Git 成功但数据库提交失败时返回部分完成诊断，不伪装成功；
- Git 非零退出且现场证明未改变时返回 `GIT_COMMAND_FAILED`；无论退出状态如何，只要现场已改变就返回 `PARTIAL_EXTERNAL_STATE`；
- Git 启动后无法证明现场是否改变时返回 `PARTIAL_EXTERNAL_STATE`、`gitState="unknown"` 和 `taskctl doctor` 建议；
- 创建部分完成后 `adopt` 只能登记 Git 已证明存在且 Repository 匹配的 Worktree；
- 删除部分完成后 `detach` 只能在期望路径匹配且现场证明不存在时清除引用；调用方路径只用于验证 `--expected-path`，精确 Git 登记复核必须使用数据库登记路径，大小写别名不能绕过陈旧登记检查；
- adopt/detach 遇到 Task version 或现场变化时拒绝，不创建、移动或删除文件；
- `doctor` 能报告数据库引用与真实 Worktree 现场不一致并给出建议命令，但不自动修复。

## 5. Session 连续性测试

- Session A 可以领取 Task；
- Session A 保存的 Checkpoint 包含下一步；
- Session B `resume` 后引用 Session A；
- 恢复输出同时包含 Task、最新 Checkpoint 和实时 Git 状态；
- Session 结束不会自动关闭 Task；
- Checkpoint 不保存 Token、密码或隐藏推理；
- 一个本地 Session 不能属于多个 Task，continuedFrom 不能跨 Task。

## 6. Hook / Runtime Adapter 后续测试

M4 阶段增加：

- 数据库唯一约束保证重复来源事件不会重复导入；
- 只采集客户端实际暴露的事件；
- 敏感字段在落盘前脱敏；
- Hook 失败不破坏手工 CLI 流程；
- Hook 事件不能自动改变 Task 状态；
- 不同客户端的特有字段不会泄漏到 Core。

## 7. 初版验收标准

1. AI 可以在指定临时 SQLite 数据库中创建并查询 synthetic Task；
2. Session A 可以携带 expected version 领取并更新 Task，旧版本写入被拒绝；
3. Session A 可以保存结构化 Checkpoint；
4. Session B 可以从同一 Task 恢复并继续；
5. Worktree 创建、状态和安全删除在临时仓库通过；
6. 所有重要变化写入 History；
7. SQLite 事务保证业务 mutation 和 History 不会部分提交；
8. 并发写入不静默丢失数据，冲突结果可以由 JSON 稳定判定；
9. 不接触用户默认数据库或真实业务仓库，不执行远程写入；
10. Git/SQLite 部分完成后可以通过显式 adopt/detach 恢复一致引用；
11. Session Import 可以去重、查询元数据并显式逻辑删除；
12. 没有 Hook 时完整流程仍然可用。

## 8. Daemon / GUI 后续安全测试

M5 阶段除功能测试外必须增加：

- 服务只绑定 loopback，拒绝非预期 Host；
- 未携带每次启动认证秘密或等价同用户凭据的请求失败；
- 默认拒绝跨 Origin，mutation 缺少 CSRF 防护信息时失败；
- 浏览器恶意站点不能借用户浏览器调用本地 mutation API；
- GUI 不默认渲染 Session Import BLOB，删除确认明确展示逻辑删除和物理擦除边界；
- 认证秘密不写入普通日志、History 或前端持久化存储。

## 日常交接回归

- active/in-progress/blocked/recent 视图的筛选正确，视图和 status 同时指定时报错；默认表格包含下一步。
- context 保留多行目标与当前版本，读取后 Task、Session、History 不变；JSON 与 Markdown 均可使用。
- here 能从 Worktree 子目录找到关联 Task，在仓库根目录返回多个候选，无匹配返回空列表，不领取任务。
- resume 的终端摘要包含目标、下一步与新 Session，JSON 合同保持不变。
