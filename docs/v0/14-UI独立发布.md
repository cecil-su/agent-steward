# UI 独立发布与免重启更新

## 边界

UI 版本包与 taskd 二进制独立交付，仍由一个 taskd 提供同源页面与业务 API，不启动独立前端服务。原生 HTML/JS/CSS 不需要 Node 运行依赖；未来构建工具或桌面壳可以产出/消费相同包合同。

**首次使用需要升级 taskd 并重启一次，以启用新托管能力。** 现有服务的升级、停启和部署必须由用户另行授权。此后，兼容的纯 UI 发布和回退不编译、不替换、不重启 taskd，不修改数据库、凭据、任务状态或 Git。后端/桌面壳升级及数据库迁移不属于纯 UI 更新。

## 包合同 1

交付物为目录，可以作为普通文件集传输。首期安装器接收已解压目录，不下载、不自动解压、不执行包内脚本。

```text
package/
  manifest.json
  index.html
  app.js
  style.css
```

示意清单（哈希必须替换为真实值）：

```json
{
  "packageFormat": 1,
  "uiVersion": "2026.09.07.1",
  "requiredApiContract": 1,
  "entry": "index.html",
  "files": {
    "index.html": "<sha256>",
    "app.js": "<sha256>",
    "style.css": "<sha256>"
  }
}
```

- 清单 UTF-8、最多 16 KiB，拒绝未知顶层字段；`files` 必须恰好列出上述三份文件。资源 UTF-8、每份最多 4 MiB。只托管白名单文件，不提供任意文件读取。
- `uiVersion` 是 1–100 个 ASCII 字母、数字、点、下划线或连字符，仅作展示。
- **release ID 是 manifest.json 原始字节的 SHA-256 小写十六进制串**；清单内哈希覆盖资源原始字节。清单序列化差异会产生不同 ID，无需跨语言 JSON 规范化。
- HTML 保留 `<head>`、`href="/style.css"`、`src="/app.js"`；taskd 返回入口时注入当前 release meta 并改为版本固定 URL。首期只支持这套三文件入口，不支持任意 chunk、路径或 Service Worker。
- 包内不包含操作系统路径、taskd、数据库、凭据或用户配置。新增资源类型/拆分 chunk 时须扩展包合同，不直接放宽任意目录托管。
- 构建期间不要修改源码。脚本会复核三份源文件哈希，但这不等于跨文件事务快照，也不替代代码/功能测试。

## 托管与切换

手工启动的新 taskd 显式指定绝对路径：

```powershell
# 示例是隔离实例，不要未经授权替换正在运行的正式服务。
.\target\debug\taskd.exe --no-open --port 0 `
  --database E:\steward-demo\tasks.db `
  --runtime-dir E:\steward-demo\runtime `
  --ui-root E:\steward-demo\ui
```

新 Windows 二进制包的 manifest 标记 `uiPackageProtocol: 1`；启动器为这种包传入 `<InstallRoot>/ui`，旧包未声明时不传新参数，以保留二进制回退兼容性。不指定 `--ui-root` 时继续只提供内嵌 UI。

```text
ui/
  update.lock
  current.json        {"release":"<manifest hash>"}
  previous.json       上次实际采用的版本，供脚本显式回退
  releases/
    <manifest hash>/  不可变完整包
```

发布脚本先完整暂存和校验，再同卷重命名安装目录，最后用临时文件替换 `current.json`。taskd 在入口和状态请求时读取指针，校验内容寻址、全部资源和兼容性后，用一个内存快照整体采用新版。失败保留运行中最近有效版本，`/ui/status` 报告错误码；重启后没有内存快照，若活动包不可用，则使用内嵌 UI 并报告错误，不声称恢复了上次外置版。

当前快照不反复读取资源文件；旧版资源按 release ID 从磁盘完整校验后提供。不要修改或删除已发布目录。没有自动清理：旧页面仍可能需要旧资源。内嵌资源 ID 也包含构建内容哈希；**跨后端升级不承诺保留上一二进制的内嵌资源**，此时页面需重新加载。

请求路径：

| 路径 | 行为 / 缓存 |
| --- | --- |
| `/` | 当前完整入口，`no-store` |
| `/ui/status` | 当前实际 release、展示版本、API 合同、是否启用外置目录及错误码，`no-store` |
| `/ui/releases/<id>/app.js`、`style.css` | 指定版本资源，`public, max-age=31536000, immutable` |
| `/app.js`、`/style.css` | 旧入口兼容路径，仍返回内嵌资源，`no-store`，新入口不引用它们 |
| `/api/...` | 原鉴权、CSRF、业务合同，`no-store` |

状态端点是与静态页面同等级的公开元数据，不包含路径、凭据或业务数据；仍执行 Host/Origin/Fetch Metadata 边界。所有静态资源继续受 CSP、nosniff、同源嵌入限制。UI 文件读取/校验在线程池执行，有并发和大小上限，不占业务 API 工作槽位。

## Windows 操作

脚本入口目前随源码提供：`distribution/windows/ui.ps1`。以下操作应在确认的安装目录和 taskd 地址上执行；它不会帮你升级或重启旧 taskd。

```powershell
# 只构建可单独交付的 UI 包，Output 必须是新目录，无 Cargo 编译。
.\distribution\windows\ui.ps1 -Action Build `
  -Version ui-20260907-1 -Output E:\steward-artifacts\ui-20260907-1

# 使用默认 InstallRoot 下 settings.json 的 IP/端口，以及 InstallRoot/ui。
.\distribution\windows\ui.ps1 -Action Activate `
  -Package E:\steward-artifacts\ui-20260907-1

# 手工启动或隔离安装时显式指定两者，UiRoot 必须对应目标 taskd 的 --ui-root。
.\distribution\windows\ui.ps1 -Action Activate `
  -Package E:\steward-artifacts\ui-20260907-1 `
  -UiRoot E:\steward-demo\ui -Url http://127.0.0.1:实际端口

.\distribution\windows\ui.ps1 -Action Status
.\distribution\windows\ui.ps1 -Action Rollback                # previous.json
.\distribution\windows\ui.ps1 -Action Rollback -Release embedded
# 也可 -Release <已安装 manifest hash>，仍校验当前 API 兼容性。
```

`Activate`/`Rollback` 在 UI 安装锁内执行，不管理进程。脚本请求 `/ui/status` 核实实际采用结果，不仅检查磁盘指针；失败尝试恢复此前实际活动指针。如果服务已不可达，回退是否已采用不能确认，需恢复连接后检查 Status，不能自动重复业务写操作。

包校验只能拒绝损坏、格式不符和已声明不兼容的包，不能判断 JS 业务逻辑是否正确。功能性缺陷使用人工回退。安装锁仅协调本脚本；不要由其他工具并发改指针。未完成的暂存目录不参与托管，可在确认无发布进行时自行检查处理，不自动清理用户目录。

## 页面更新与兼容边界

页面每 10 秒尝试检查实际活动 release；后台浏览器节流可能延迟，不承诺精确 10 秒生效。页面打开后先记录入口 meta 的版本，避免首次检测时把新版误当成自己已加载的版本。

- 空闲时自动重新加载，不做运行中 JS 热替换。
- 打开操作表单、填写登录凭据、存在尚未应用的搜索输入、提交进行中或写入结果不确定时，保留页面并提示新版就绪。
- 一旦因编辑/提交而暂缓，本次更新不在表单关闭后突然自动刷新；由用户显式点击“刷新采用新版”并确认。提交进行中仍拒绝刷新。
- 检查失败不干扰业务，也不会重放请求。回退采用同一机制。
- 这不会保护用户自己点击浏览器刷新/关闭窗口的行为，也不新增表单持久化。

API 合同当前为整数 `1`，与数据库 schema 和 JSON envelope `schemaVersion=2` 分开。首期严格相等，不实现版本范围或自动适配。包声明不兼容时 taskd 拒绝采用；新版 UI 的业务请求携带 `X-Steward-UI-Contract: 1`，后端在业务处理前拒绝不匹配的请求（409 `UI_API_INCOMPATIBLE`）。不携带此头的既有 CLI/脚本继续使用原合同，兼容头不是认证凭据。

未来破坏性 API 改动须同步更新服务常量、内嵌 UI 请求头、打包合同及测试；旧外置包被拒绝。加字段等真正向后兼容的变更可维持合同版本。声明相等不替代回归测试，也不保证发布者错误标记的包正确运行。

## 信任与未来桌面化

UI 包是会在已授权页面运行的代码，不是普通用户数据。只安装经过审查的可信包；安装目录及其父目录须由可信本地用户控制。taskd 拒绝资源、包目录及 store/release 层的符号链接/Windows reparse point，但不把此检查当作抵御拥有本地写权限攻击者的沙箱或无竞态文件系统保证。

哈希仅保证内容一致性，**不认证发布者**。不提供在线下载、签名体系或 HTTP 上传安装。以后桌面/在线更新器必须另外实现发布签名验证及可信更新渠道。

未来 Tauri/Electron 壳可启动/连接 taskd，让 WebView 加载同源地址，复用 UI 包与业务 API。平台脚本只是安装入口，不是 taskd 运行依赖。桌面单实例、进程管理、安全授权交接、安装签名及二进制更新仍需另行实现；取消 HTTP 改桌面 IPC 时仍需调整通信层。

## 自动化检查

```powershell
cargo test -p steward-server --locked
cargo clippy -p steward-server --all-targets --locked -- -D warnings
node --test crates/server/tests/browser/*.test.cjs
cargo build -p steward-server --locked
pwsh -NoProfile -File distribution/windows/test-ui.ps1
pwsh -NoProfile -File distribution/windows/test-local.ps1
pwsh -NoProfile -File distribution/windows/test.ps1
```

`test-ui.ps1` 只启动临时端口、临时数据库/runtime 的隔离 taskd，通过真实 HTTP 检查 A/B 切换、旧资源、回退、损坏拒绝、内嵌回退及 PID/启动时间不变，最后用专属停止标记正常退出，不强杀。Node 测试为 DOM/VM 自动化，不等于真实浏览器人工验收。正式部署、跨平台运行、桌面壳及用户验收需分别记录，不能由测试通过推断。
