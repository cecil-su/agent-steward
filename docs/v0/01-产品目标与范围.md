# 产品目标与范围

## 1. 产品定位

`taskctl` 是一个使用 Rust 实现的本地优先任务上下文 CLI。它帮助人类和 AI 在不同窗口、不同 Session 之间持续推进任务，并提供轻量 Git Worktree 快捷操作。

任务数据保存在本机 SQLite 数据库中，由 CLI 直接访问，不需要独立数据库服务。它管理的是任务意图、当前进度、恢复上下文和工作目录引用，不替代业务需求、Git 事实或人工验收。

## 2. 目标使用场景

### 创建任务

用户打开一个专门的 AI 窗口，由 AI 整理任务目标、范围、验收条件和下一步，再通过 CLI 创建或更新 Task。

### 领取和继续任务

执行窗口通过 Session ID 领取 Task。执行期间由 AI 主动更新状态、关键决策、阻塞和 Checkpoint。换 Session 或换窗口后，通过 `resume` 读取 Task、最新 Checkpoint、Session 历史和当前 Git 现场，继续推进。

### Worktree 快捷操作

CLI 封装常用的 `git worktree` 创建、状态和删除命令。初版不建设复杂的计划与审批系统，由人决定何时使用；工具只保留必要的路径校验和 dirty 删除保护。

## 3. 当前能力

- 在本机 SQLite 数据库中创建、查询、更新、阻塞、解除阻塞和关闭 Task；
- 通过 Session 领取和恢复 Task；
- 保存备注、最新 Checkpoint 和 Session 历史；
- 对用户明确导入的 Session 内容提供 SHA-256 去重、元数据查询和逻辑删除；
- 保存 Repository 路径、规范化 common-dir 身份、Branch 和 Worktree 引用；
- 实时读取 Worktree 的 HEAD、dirty、staged 和 untracked 状态；
- 追加轻量 History，并在 Git/SQLite 部分完成后通过显式、非破坏性的 adopt/detach 命令修复引用；
- 同时提供人类可读输出和稳定 `--json` 输出；
- 支持从 AI 客户端提供的 Session 文件或记录路径建立引用；
- 使用跨平台 CanonicalPath 和 Git common-dir 身份保护 Worktree 操作。

## 4. 权威边界

| 事实 | 权威来源 |
| --- | --- |
| 任务目标、状态、阻塞、Checkpoint、当前 Session | 本机 SQLite 数据库 |
| Session ID、来源、记录路径和继续关系 | 本机 SQLite 数据库 |
| Repository 路径、规范化 common-dir 身份、Branch 和 Worktree 引用 | 本机 SQLite 数据库 |
| HEAD、dirty、staged、untracked、Worktree 实际存在状态 | Git 与文件系统实时观察 |
| 原始 AI 聊天记录 | AI 客户端自身记录；初版只在用户明确导入时保存副本或保存外部路径引用 |
| 重要变更历史 | 本机 SQLite 数据库 |

## 5. 当前非目标

- 多 Agent 分派、角色编排和自动验收；
- Owner/Ownership 权限生命周期；
- Event、Ack、Evidence 等独立领域模型；
- 通用 Operation Plan、Approval、UNKNOWN/reconcile 状态机；显式 Worktree adopt/detach 只修复已证明的引用不一致，不扩展为通用执行框架；
- 自动 commit、merge、push 或 force 操作；
- 自动保存模型未向客户端暴露的隐藏推理；
- 分布式、多租户服务；
- 多台机器共享同一数据库。

本地taskd提供HTTP与只读Web工作台；HTTP具有admin/reader访问角色，不建立领域Owner/Approval模型。

## 6. 关闭结果

Task 保留简单关闭结果字段：

- `completed`：约定范围完整完成；
- `partial`：用户接受已记录的残余事项；
- `cancelled`：用户取消；
- `superseded`：被其他 Task 替代。

关闭记录必须如实说明未验证项和残余风险。AI 的摘要、Session 结束或测试输出不能自动关闭 Task。

关闭转换固定为：`completed` 只允许从 `in_progress` 进入；`partial` 允许从 `in_progress/blocked` 进入且必须记录残余事项；`cancelled/superseded` 允许从任意未关闭状态进入且必须提供原因。Task 关闭后不允许重新打开、普通更新或保存 Checkpoint；V0 不提供 reopen。显式 CAS `task retitle` 可修正已关闭任务标题；Session Import/Hook 清理与 Worktree 引用管理按各自合同执行，不视为重新打开任务。
