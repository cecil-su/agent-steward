# 产品目标与范围

## 定位

Agent Steward 是用户主导的本机任务数据中心，保存任务意图、资料、当前业务状态和会话连续性记录。AI 可以辅助理解和执行用户要求，但不得依据测试、摘要、交付或会话结束自行决定任务完成。

任务数据由 Application Service 写入 SQLite；CLI/HTTP共用合同。页面只读，正文支持安全Markdown展示，不把Markdown文件变成权威任务库。

## 状态与记录

Task 有 backlog（暂不开始）、todo（默认，等待开始）、in_progress（执行中）、in_review（已交付待审核/验收）、blocked（受阻）、done（完成）、cancelled（不再推进）。用户可直接选择任一状态，无领取、描述完整、开发、审核、阻塞说明或上线前置条件。

`task status` 是唯一业务状态入口；保留合法值校验、CAS、事务及History。创建默认todo；同状态请求也校验CAS。状态变化不清空下一步、Note、Checkpoint、旧关闭结果或Session。

Session关联/继续/结束是显式独立操作。claim/resume不改变业务状态；读取任务、打开窗口及宿主事件不隐式领取、接管或恢复旧Session。done/cancelled可以重新转为其他状态，不需要reopen流程。

## 能力范围

- Task创建、查询、描述/归属维护、状态设置、Note、Checkpoint和History。
- Project/Component、源码绝对路径资料、带任务来源的项目资料、global/project规则。
- 显式Session元数据、继续关系、敏感内容审查后的文件导入/去重/逻辑删除。
- Hook仅记录明确绑定会话的白名单事件元数据，不记录正文、不推断业务结论。
- 只读Web查询任务、项目、Note、Session、历史、有效规则及复制任务上下文。
- 显式离线迁移到新数据库，不自动切换正式实例。

## 权威边界

| 数据 | 权威及限制 |
| --- | --- |
| 任务、项目、规则、Session关联、Checkpoint、History | 本机SQLite；版本与修订分别CAS |
| 源码路径 | 用户登记的普通资料；不证明存在、身份或可访问性 |
| 项目资料、Note与验收说明 | 带来源的用户/AI记录，不是工具自动验证的事实 |
| 原始聊天 | 客户端自身记录；仅显式导入时保存审查后的副本 |
| Git、源码内容、运行与测试现场 | Steward不采集；执行者使用独立工具核实 |

## 不提供的能力

Worktree创建/删除/登记/解除、主动Git查询、源码目录探测/导航/正文读取均不在范围内。无自动commit/merge/push、领域Owner/Approval、任务流程编排、自动验收、完整聊天扫描或隐藏推理采集。不支持多个OS用户或多机器共享业务库。

HTTP有admin/reader访问角色，但这不是任务领域Owner模型。Session、任务状态、资料路径和Hook事件都不授予部署、远程写入或业务验收权限。

## 历史兼容

旧closed的completed映射done，partial/cancelled/superseded映射cancelled；原关闭结果、原因、时间仍保留历史含义。旧open→todo，pending_release→in_review，in_progress/blocked不变。历史迁移不伪造用户操作、不重写旧History、不恢复旧Session。详细安全合同见 [迁移](18-Schema7隔离导入与验证.md)。
