# v7 归档导入

`database import-v7`是当前CLI的显式离线归档入口，不是普通打开时的自动升级，也不是任意SQLite库合并工具。

## 输入与前置条件

- 源为`user_version=0`、schema_migrations含版本1–7且布局匹配的普通数据库快照。此输入格式与目标Schema7不同。
- 全部Task须已关闭，无当前执行Session及Worktree绑定。tasks.worktree_path_key仅允许NULL；歧义taskKey、未知表/列、损坏数据拒绝。
- 先停止源写入者，使用SQLite Backup API取得包含已提交WAL的一致快照；不能只复制运行中数据库的主文件。
- 源/目标必须显式绝对路径；目标及-wal/-shm/-journal全部不存在，包括链接。复制前及发布前复核，不删除占用路径、不合并或覆盖。源与目标目录须由操作者控制。

## 隔离调用

CLI/SOURCE/NEW_DB替换为核验的可执行文件、合成或获准停写快照、不存在的隔离目标绝对路径。

```text
CLI --json database import-v7 --help
CLI --database NEW_DB --json --yes database import-v7 --source SOURCE
```

`Service::import_legacy_v7`以READ_ONLY/query_only及固定读事务打开源，校验Schema、表列、Task范围、quick_check及外键；在同目录私有暂存库中初始化Schema7并单事务复制Task、Session、Checkpoint、Note、History、Import。

保留ID、version、时间、状态、继续关系、JSON原文、Import BLOB及自增高水位，逐字段比对并核验完整性/应用读取。关闭并刷盘后，以不覆盖的hard link发布；文件系统不支持hard link即失败，不降级覆盖。

源格式元数据schema_migrations不导入，NULL的tasks.worktree_path_key不进入目标。目标session_events为空；tasks.project_id为空，projects/project_history/components/repositories/source_roots/task_components/project_profiles/rules/rule_history为空。不从文本推断项目或规则，不创建业务History或递增任务版本，不重开任务。

## 失败与验证

失败不发布部分目标，只清理本命令创建的暂存；源不写入，已有目标不动。复制不安装二进制、不切换默认路径或宿主配置、不启动服务。

- 显式指定目标读取Task、Session、History、Notes和Import元数据；只有登记的外部路径也获准时才运行可能观察它们的doctor/context。
- 比对复制字段、计数、自增高水位及关闭状态，保留源快照；后续写入测试在目标副本上执行。
- 自动化入口：`cargo test -p steward-application --test migration --locked`、`cargo test -p taskctl --test migration_contract --locked`。

其他输入格式须使用[对应导入命令](18-Schema7隔离导入与验证.md)，不能修改源版本号冒充兼容。正式切换和恢复需要独立停写、备份、路径及配套程序核验；新库接受写入后不能直接覆盖备份或只降级程序。复制成功不证明业务验收、断电耐久性或跨平台兼容。
