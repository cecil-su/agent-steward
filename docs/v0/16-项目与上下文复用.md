# 项目、源码路径资料与任务上下文

当前源码合同：Schema8、业务envelope3、UI合同5、包格式1。普通连接不升级旧库，源码合同不证明正式部署。Steward是数据中心，不提供Worktree管理、主动Git查询或源码读取。

## Project与Component

- 项目id为不可变、不复用的正整数；引用接受数字、`##数字`或唯一名称。Task使用`#数字`，两者不混用。
- 项目名trim后NFC，显示保留大小写，唯一键只折叠ASCII A–Z；1–120 Unicode字符，拒绝控制字符、纯ASCII数字和#开头，不建立旧名别名或相似匹配。
- ProjectView为id/name/revision/createdAt/updatedAt；revision初始1。创建/改名及History同事务，改名不改变Task或Session。
- Component名字规则相同，唯一范围为所属项目；每项目最多200项。组件不等于目录或执行所有权。
- Task可关联一个项目、选择该项目内的组件；componentIds升序唯一，由关系表派生。project/component复合外键阻止跨项目关联。

```text
taskctl --database TEST_DB --json project create --name PROJECT_NAME
taskctl --database TEST_DB --json project show PROJECT
taskctl --database TEST_DB --json project list --after 0 --limit 50
taskctl --database TEST_DB --json project rename PROJECT --name NEW_NAME --if-revision REVISION
taskctl --database TEST_DB --json project history PROJECT --after 0 --limit 50
taskctl --database TEST_DB --json project component add PROJECT --name COMPONENT --if-revision REVISION
taskctl --database TEST_DB --json project component list PROJECT
```

list按ID，history按revision升序，after为上次末值、limit默认50且1–200，返回hasMore/nextAfter；不保证跨页静态快照。

任务创建可用--project或输入project；同时指定时必须解析为同一项目。归属/组件修改用Task version，不改变Project revision或业务status/Session；须明确确认与依据，有旧组件时换项目必须同时指定新components或[]，不静默丢弃。详见 [信息维护](20-任务信息维护.md)。

## 源码路径仅作资料

SourceRootView：`id/projectId/componentId/directoryPath/createdAt`。不再有Repository、common-dir、相对路径或对象身份字段。

```text
taskctl --database TEST_DB --json project source add PROJECT --directory ABSOLUTE_PATH [--component COMPONENT] --if-revision REVISION
taskctl --database TEST_DB --json project source list PROJECT
taskctl --database TEST_DB --json project source remove PROJECT SOURCE_ID --if-revision REVISION
```

- directoryPath为UTF-8绝对路径文本，最多4096字节，无控制字符；可表示不可用驱动器或另一机器路径，不要求存在。
- 不检查Git标记、不canonicalize、不探测目录/文件、不读取源码；不将路径字符串作为实际文件身份或权限证据。
- 添加/解除使用Project revision CAS，同事务写source.added/source.removed。每项目最多200条，组件须属于项目；重复关联拒绝，不消耗revision。
- source list只读取元数据，删除只移除该关联，不删除磁盘目录、源码或组件。路径失效不妨碍解除资料关联。
- `--repo/--path/--worktree`源码参数、project here/context/source resolve、task here、所有Worktree命令及源码/Git HTTP查询已移除，无兼容探测分支。

## HTTP与页面

只读路由：

- GET /api/projects?after=0&limit=50
- GET /api/projects/{ref}
- GET /api/projects/{ref}/history?after=0&limit=50
- GET /api/projects/{ref}/components、/sources
- GET /api/tasks?project=... 及 /api/tasks/{id}/context

名称/##引用须URL编码。源码列表只显示登记文字；没有源码导航/文件正文端点。两套Web均只读，不因admin角色出现业务写入口。

管理员写命令使用POST /api/commands/{command}严格JSON：

| command | 字段 |
| --- | --- |
| project-create | name |
| project-rename / project-component-add | projectId/expectedRevision/name |
| project-source-add | projectId/expectedRevision/location；component可选 |
| project-source-remove | projectId/expectedRevision/sourceId/confirmed=true |
| task-project | taskId/expectedVersion/confirmed=true/reason；project与clear二选一 |
| task-components | taskId/expectedVersion/components/confirmed=true/reason |

location仅 `{"kind":"directory","path":"E:/synthetic/source"}`；拒绝git类型或额外字段。HTTP路径输入仍满足传输层绝对路径校验，但不会读取登记源码。reader在业务写请求体解析前被拒绝。权限、Origin/CSRF与容量见 [HTTP合同](11-Hook与HTTP合同.md)。

## Task上下文

`task context`在同一只读数据库事务内读取Task/Project/项目资料/有效规则/最新Checkpoint/当前Session及检查点后的Notes。没有Git或源码观察，不根据目录选项目或任务，不建立Session关联。

检查点边界按checkpoint.saved History的checkpointId/sequence定位，不用同毫秒时间判断；只返回最新50条Note，notesTruncated及CONTEXT_NOTES_TRUNCATED明确说明，完整内容用task notes。无检查点从历史起点算。Project、规则和资料只是上下文，不授予执行权限。

任务列表project筛选绑定解析后的项目ID到游标摘要，同项目改名后可按ID续页；不同项目不得混用游标。清除筛选不是清除归属。resume仍为显式Session写操作，不是只读导出。

## 宿主证据基础库的独立边界

无项目事实持久缓存、完整依赖闭包或源码复用许可。HostEvidence基础库不是源码读取CLI/API，也未自动证明Pi真实加载或工具配置。

- protocolVersion=1，严格拒绝未知字段；独立预期绑定与实时时钟不能来自报告自己。最长五分钟有效期，未来时间/过期/回退拒绝。
- 显式宿主规则证据可由基础库核对已报告规则文件的内容/对象摘要和缺失状态，最多64规则/64工具，规则单文件256KiB、每轮4MiB、双次读取；这是规则证据核验，不再提供项目源码导航或正文查询。
- 活跃路径身份在双次核验期间保留，持久摘要不能证明跨进程连续性；工具配置/可用性仍是报告，不执行工具核验。输出始终hostClaimVerified=false/reuseAllowed=false，不写业务库/History/缓存。
- HostContextRequest仅含task/task_version/session_id/source_id；bindingVersion=2绑定数据库身份、Task/version/组件、当前未结束Session、Project及已登记SourceRoot资料，不绑定源码内容、Git或文件请求。
- 应用层从数据库独立核对归属、CAS及当前Session，前后复核资料和时间；业务状态不限制该读取。非同项目或超出Task已选组件的来源拒绝。

Pi实验模块及未贯通/真实宿主验证限制见 [集成说明](../../integrations/README.md)。不能把规则摘要一致、资料路径或通过测试解释为完整宿主证据、源码已验证或业务授权。

## 迁移与验证

旧源码资料与状态按 [Schema8显式迁移](18-Schema7隔离导入与验证.md)转换，Git源码必须由操作者明确提供绝对路径，禁止从common-dir猜工作区。旧History原文不改，不按任务文字猜projectId。

自动化入口：application的projects/sources/project_profiles/task_maintenance与host_context测试、CLI/HTTP的projects测试及Web展示测试。全部使用合成数据；路径资料登记测试不需要访问真实源码。实际部署、平台、人工验收和外部宿主接入分别验证。
