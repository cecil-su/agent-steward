# 总体架构

## 入口与权威来源

```text
人类 / AI ── taskctl CLI ──────────┐
宿主事件 ── task-hook ──────────────┤
只读React Web ── taskd HTTP ────────┤
                                  ▼
                         Application Service
                           ├─ SQLite
                           └─ Git Adapter ── Git / 文件系统
```

SQLite保存在服务所在本机，是Task/Project/Rule/Session/Checkpoint/History的权威来源；Git HEAD、分支、dirty和Worktree存在性来自实时观察。多个本机入口可访问同一数据库，不需要独立数据库服务，不支持跨机器共享数据库文件。

## Cargo Workspace

| crate | 职责 |
| --- | --- |
| `core` | DTO、状态和输入规则、默认目录与跨平台权限辅助 |
| `application` | `Service`门面、业务用例、事务、CAS、诊断和恢复建议 |
| `storage-sqlite` | 连接、Schema7初始化、WAL、busy timeout、路径与版本检查 |
| `git-adapter` | 原生路径身份、任务锁、Git观察及显式本地Worktree操作 |
| `cli` | taskctl参数/输入/输出；task-hook元数据投影 |
| `server` | taskd HTTP、认证、SSE、UiStore |

React源码为`web/src`；内嵌快照为`crates/server/web-readonly`。`Application`直接使用rusqlite编写事务和SQL，storage-sqlite不是完整Repository抽象层。Core不依赖Application、SQLite或Git；HTTP使用异步运行时，同步业务及认证数据库工作进入有界阻塞执行器。

代码位置和测试见[CODEMAP](../../CODEMAP.md)。V1设计中的同名组件不代表这些V0实现。

## 事务与进程模型

1. CLI解析参数、显式输入和数据库路径；独立于数据库的输入校验先执行。
2. 普通连接检查版本，仅空库允许事务初始化Schema7；不兼容库拒绝。专用task context只读连接不初始化文件或表。
3. Query读取快照；mutation使用调用方提供的最新expected version/revision，在写事务内复核并保存业务变更及History。
4. Git操作在SQLite写事务外执行。Worktree mutation持任务级advisory lock，Git后再复核现场与数据库结果。
5. CLI返回人类文本或JSON envelope后关闭连接；taskd常驻，通过SSE发送数据失效通知，客户端重新读取。

Task version、Project revision和Rule revision分别管理。冲突不得自动用新版本重放旧Patch。Git和SQLite不能原子提交，部分完成只能返回诊断及经验证的显式恢复建议。

## 接口边界

- Web只读；CLI和获准的管理员HTTP命令通过Application维护业务，不直接修改SQLite。
- Hook只投影实际提供的元数据，不能根据聊天、工具输出或生命周期事件修改Task结论。
- JSON业务envelope为`schemaVersion:2`，包含`ok/data/warnings/error`，诊断不污染stdout。
- UI API合同4、包格式1，与数据库Schema和JSON envelope独立。
- 写入响应丢失不表示回滚；先重新读取结果，不能自动重放create/resume/Git写操作。
- 不提供持久化Operation、请求级exactly-once或通用Agent编排。

认证、并发容量和取消限制见[HTTP合同](11-Hook与HTTP合同.md)；文件权限、路径及删除竞态见[安全与事务](05-安全与事务.md)。
