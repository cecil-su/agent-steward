# 总体架构

```text
人类 / AI ── taskctl ────────────┐
宿主事件 ── task-hook ────────────┤
只读Web ── taskd HTTP ────────────┤
                                ▼
                       Application Service
                                │
                         本机 SQLite
```

Steward是用户主导的数据中心，不调用Git或读取项目源码。源码路径只作资料；宿主规则证据核验、显式Session Import、数据库/UI包的必要文件操作不等于源码浏览能力。

## Workspace

| crate | 职责 |
| --- | --- |
| core | DTO、七状态、输入规则、默认目录及平台权限辅助 |
| application | Service用例、事务/CAS/History、path_safety、显式迁移和诊断 |
| storage-sqlite | Schema8、连接/只读连接、WAL与有限busy timeout |
| cli | taskctl输入输出、task-hook元数据投影 |
| server | taskd HTTP、认证、SSE、UiStore |

Application直接使用rusqlite，不引入通用Repository抽象。git-adapter及Worktree/源码读取模块已移除。React源码在web/src，内嵌快照在crates/server/web-readonly，旧原生只读页面在crates/server/web-legacy-readonly。代码位置见 [CODEMAP](../../CODEMAP.md)。

## 一致性模型

1. 独立于数据库的输入校验先执行，普通连接只打开当前Schema或原子初始化空库。
2. Query读取数据库快照；task context使用专用只读连接，不初始化缺失/空库。
3. Mutation接收调用方expectedVersion/revision，IMMEDIATE事务内复核、写业务及History，失败全部回滚。
4. Task version、Project revision、Rule revision互相独立；冲突重新读取判断，不把服务现读版本填回旧Patch。
5. status仅更新业务状态；Session操作不改status，Hook事件不触发业务或Session生命周期。
6. taskd同步工作进入有界阻塞执行器；SSE仅提示已提交数据失效，页面重新查询，不重放写请求。

SQLite是本机业务权威，不支持跨机器共享库。无Worktree锁或Git/SQLite部分提交协议。响应丢失仍需核对已提交结果，不提供请求级exactly-once或自动补偿。

## 接口合同

CLI/HTTP业务JSON envelope3、UI API合同5、包格式1，与Schema8独立版本管理。Web均只读，管理员HTTP及CLI维护业务；认证、Origin/CSRF和reader拒绝不因页面隐藏写按钮而省略。

只读/写入及授权边界见 [安全](05-安全与事务.md)、[HTTP](11-Hook与HTTP合同.md)。V1是独立设计，不从V0推定其实现或自动升级关系。
