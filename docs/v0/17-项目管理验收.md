## 3. 用例

以下命令中的`CLI/TEST_DB/PROJECT/TASK/REVISION/VERSION`均须替换为核验值；数字来自刚读取的响应，不复用示例版本。

### TC-P1 项目创建与改名（隔离库写入）

1. 从新的Shell运行：`CLI --database TEST_DB --json project create --name P-A`，记录ID/revision；不登记源码。
2. `project show PROJECT`确认项目可独立存在；以P-A同名及ASCII大小写等价名称再次创建，预期拒绝，无重复项目。
3. 重新`project show`后运行`project rename PROJECT --name NEW_NAME --if-revision REVISION`。
4. 新开工作台，进入“项目”，核对ID、名称及修订。

预期：改名保持ID，只推进Project revision及项目History；不创建Task/Session/Worktree。页面仅查询，不出现新建/编辑/改名业务按钮。证据：CLI退出码/envelope、前后项目快照、页面自然GET。

### TC-P2 组件与源码（隔离库写入，不改源码）

1. `project show PROJECT`后运行`project component add PROJECT --name C-A --if-revision REVISION`。
2. 使用新的revision运行`project source add PROJECT --component C-A --repo SRC-G --path . --if-revision REVISION`。
3. 再读revision，运行`project source add PROJECT --directory SRC-D --if-revision REVISION`。
4. `project source list PROJECT`核对类型/组件/路径；再读revision后，对SRC-D运行`project source remove PROJECT SOURCE_ID --if-revision REVISION`。

预期：每次有效维护只推进Project revision；解除只移除元数据，SRC-D及文件保留，SRC-G的HEAD/status/hash不因登记改变。错误/越界路径拒绝。证据：源码ID、项目History和文件基线。

### TC-P3 任务归属与组件（隔离库写入）

1. `task show TASK`记录执行字段及version。
2. `task project TASK --project PROJECT --if-version VERSION --yes --reason REASON`；重读version。
3. `task components TASK --component C-A --if-version VERSION --yes --reason REASON`。
4. 在另一隔离任务上关联P-B，确认不串项目。
5. 已有组件时尝试仅换项目/清归属，预期拒绝；明确需要清除时用`task update TASK --if-version VERSION --yes --reason REASON --input PATCH_FILE`，文件为`{"project":null,"components":[]}`。

预期：实际维护推进Task version并记录History，不改变状态、Session、Worktree或Project revision。缺确认/依据、旧CAS及跨项目组件拒绝且不部分更新。证据：前后快照、错误code、History。

### TC-P4 查询、筛选与上下文（只读）

1. 新开工作台“项目”，选择P-A，再查看关联任务；任务查询切换项目/状态/搜索，确认没有P-B行混入。
2. 清除筛选，确认只是恢复查询范围，不解除归属。
3. 打开T-A，核对项目、组件、资料、有效规则和Notes；复制上下文，核对Task版本及截断提示。
4. 用CLI运行`project context PROJECT --source SOURCE_ID --worktree SRC-G`。未提供`--file`时不返回源码正文；错误或缺少Git工作区不静默兜底。
5. 前后读取Task/Project版本及History。

预期：查询不改版本/History、不claim/adopt；导航仅代表已观察现场，不证明完整依赖或允许缓存复用。证据：自然GET过滤参数、脱敏复制文本、版本和History。

### TC-P5 CAS、分页与窄屏（隔离写入/只读）

1. 两Shell读取同一Project revision；A改名成功，B使用旧revision改名，预期VERSION_CONFLICT、无覆盖。B重读并由人重新审查，不自动重放。
2. Task维护同样核对独立version，不把Project revision当Task version。
3. 有PAGE-A时加载第二页，切换条件后核对行ID/游标不跨范围；缺数据则分页项BLOCKED。
4. 在390px视口检查任务/项目详情、长路径、只读上下文无横向溢出。

证据：CAS错误、前后快照、页行ID、自然请求及截图。响应丢失/恶意参数优先引用自动化合同证据，不在共享环境拦截或重放请求。

### TC-P6 权限与兼容（只读）

1. 新浏览器上下文以READER连接专用严格认证实例，读取项目/任务/源码导航。
2. 确认admin与reader页面均无业务写入口；认证登录/退出POST不计业务写入。
3. reader拒绝业务写请求的后端保护引用`crates/server/tests/projects.rs`，不手工攻击共享实例。
4. UI合同不匹配时应明确拒绝，不改旧manifest号伪装兼容；缺专用不匹配合同的测试包/环境则该子项BLOCKED。

证据只保存角色、页面入口、状态/error.code，不含Cookie/Token。

### C-01 组合

按P1→P2→P3→P4→P5/P6执行；在新窗口重新定位项目、任务并读取上下文。完成查询不等于业务验收完成或Task可自动关闭。
