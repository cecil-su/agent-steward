# Task Control Plane

> 本文是 Task Control Plane 的 V0 独立项目概览，已随 V0 合同勘误同步修订，不是原始版本的逐字快照。V0、V1 以及未来可能出现的 V2 不构成必然的继承或升级关系；本文只描述 V0，不能用于推断其它方案的范围或完成度。

本项目用于规划并逐步实现一个本地优先的任务上下文工具。人类和 AI 可以通过 `taskctl` 创建、领取、更新和恢复任务，并使用轻量 Worktree 命令隔离工作目录。

初版使用 Rust 开发 CLI，任务数据保存在 CLI 直接访问的本机 SQLite 数据库中，不依赖独立数据库服务，也不支持多台机器共享同一数据库。Cargo workspace 中现已提供对应 V0 合同的 `taskctl` 参考实现；它用于验证 V0 本地闭环，不代表、替代或预先实现任何其它版本方案，也不进行全局环境集成。

## 初版目标

- 用一个专门的 AI 窗口创建和整理 Task；
- 在执行窗口中领取 Task，并更新状态、备注和阻塞信息；
- 保存 Session 关联和结构化 Checkpoint；
- 切换 Session 或窗口后，通过 Task 恢复上下文并继续；
- 提供简单的 Worktree 创建、状态和删除命令；
- 为 AI 提供稳定的 `--json` 读写合同；
- 通过调用方 expected version 防止旧上下文静默覆盖；
- 追加轻量 History，记录重要变更；
- 在 Git/SQLite 部分完成后提供显式、非破坏性的 Worktree 引用恢复命令；
- 使用跨平台路径和 Git common-dir 身份保护 Worktree 操作；
- 允许用户查询、去重和逻辑删除明确导入的 Session 副本。

初版由 AI 在关键节点主动调用 CLI 更新数据。AI Client Hook 和 Runtime Adapter 作为后续自动采集能力加入路线图，但不能替代显式 Task 更新，也不能根据聊天内容自动宣告任务完成。

## 当前结论

初版只围绕 Task、Session、Checkpoint、Worktree 和 History 建立可运行闭环。Repository、关闭结果等作为 Task 字段保存在 SQLite 中，Git 现场仍由 Git 和文件系统实时提供；不创建独立的 Owner、Assignment、Event、Operation 或 Approval 模型。出现真实使用需求后，再逐步增加自动 Hook、Runtime Adapter、Daemon 和 GUI。
