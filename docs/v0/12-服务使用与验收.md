# 服务使用与验收

本指南描述V0当前服务，与V1独立。接口见[Hook与HTTP合同](11-Hook与HTTP合同.md)。

## 安装与启动

```bash
cargo build --workspace --locked
# 可选：安装到 Cargo bin 目录（taskctl + task-hook，以及 taskd）
cargo install --path crates/cli --locked
cargo install --path crates/server --locked

# 使用新的隔离数据库启动本地工作台
cargo run -p steward-server --bin taskd -- --database /tmp/steward-service-demo/steward.db
```

服务默认监听 `http://127.0.0.1:43123`，可以收藏这个固定地址；`--port <端口>` 可更改，`--port 0` 专用于临时端口。端口占用时启动失败，不静默换地址。显式 `--bind <本机IPv4>` 可改为指定网卡地址（不允许 `0.0.0.0`、广播或多播）；页面必须使用启动输出的精确 IP 和端口，Host/Origin 校验保持开启，默认真实 TCP 来源是回环地址或监听网卡 IP 时直接作为管理员；本机通过自己的监听IP直接访问也免登录。不使用 HTTP 转发头判断本机。此模式信任本机所有用户与程序，禁止代理/隧道/端口转发此服务；需要代理时必须加 `--require-local-auth`。非回环 HTTP 会暴露到该接口，凭据与任务数据不加密传输，仅在受控网络试运行；程序不会修改防火墙。

终端显示页面 URL 和凭据文件路径，不显示凭据内容。默认启动后自动打开本机浏览器并连接，无需复制凭据；无桌面/自动化场景传 `--no-open`。默认自动打开普通网址，本机直接访问不需要 Cookie 或连接码。

只有 `--require-local-auth` 严格模式的自动连接使用仅在内存保存的随机一次性连接码，120 秒过期，通过 URL fragment 交给本机浏览器（不打印完整链接），页面立即清除 fragment，再用 `POST /api/connect` 兑换本机管理员的浏览器授权 Cookie，不向页面返回管理员凭据。兑换同样检查 Host/Origin，连接码仅可成功消费一次且不能直接调用业务接口。远程请求仍要求凭据；缺少 TCP peer 或含 Forwarded/X-Forwarded-* 不获得本机特权。浏览器启动失败或链接失效时可手动连接；其他设备只分发终端显示的 `Read-only credential file` 内容。

首次启动在私有 `runtime/identity` 目录生成管理员 `credential` 和只读 `readonly-credential`，后续启动复用，退出不删除。远程权限由凭据决定；不要把管理员凭据分享给只读设备。

首次授权后通过 30 天有效的 HttpOnly、SameSite=Strict Cookie 记住浏览器；普通网址、新标签页、刷新及同地址重启均可恢复，不在 JS 存储中保存长期凭据。禁用 Cookie 不影响默认本机免登录，但远程/严格模式无法建立浏览器登录。退出登录会撤销本浏览器授权；管理员点击“撤销浏览器授权”可撤销当前地址全部浏览器授权（含自己），但不会轮换凭据文件，也不会关闭本机免登录。本机免登录界面不显示“退出登录”，避免误以为退出能撤销本机权限。

授权的哈希及角色保存在私有 identity/browser-sessions.db，最多 256 项；服务端校验过期时间和长期凭据绑定。如需撤销泄露的凭据，先停止所有使用该 runtime 目录的 taskd，明确删除对应的 identity 凭据文件，再启动生成新值；损坏或不安全的已有文件会被拒绝，不静默覆盖。切换端口会改变服务 origin 和授权匹配范围，需重新建立对应授权，自动连接仍可使用。

`--runtime-dir` 可指定现有私有目录或尚不存在的新目录。已有目录如果对其他用户开放会被拒绝，不会自动更改共享目录权限。GUI 静态 HTML/CSS/JavaScript 保留内嵌兜底；新 taskd 可通过 `--ui-root <绝对路径>` 托管独立 UI 包，后续兼容的纯 UI 更新无需重启。无 Node、React、外部 CDN 或独立前端服务运行依赖。详见 [UI 独立发布](14-UI独立发布.md)。

**数据库格式：**当前源码使用 SQLite `user_version=7`。普通连接只初始化空库，非空的非7数据库拒绝打开，不隐式迁移、删除或重建。Schema2/4/5/6各有显式复制到新库的命令；import-v7接受schema_migrations格式归档，不等于当前Schema7，准确入口见[隔离导入](18-Schema7隔离导入与验证.md)。HTTP/taskctl JSON业务envelope为2，UI API合同4，与数据库版本分别管理。

Windows 免编译发布包、启动与更新入口见 [Windows 使用指南](../../distribution/windows/README.md)。更新器仅管理自己启动的进程；已有手工启动的服务需要用户先停止并核对数据库/runtime 路径，不自动接管。

## GUI 工作流

1. 在只读工作台检索任务、按状态/项目筛选并查看详情；页面不提供新建或编辑业务入口。
2. 查看目标、范围、验收、下一步、Checkpoint、项目资料和有效规则。
3. “会话”查看继续关系、Hook观测和Import元数据；“代码现场”显示登记路径与实时Git观察，不创建、删除、adopt或detach。
4. 复制最新交接上下文；剪贴板不可用时手工复制只读文本。查询不会领取、恢复或关闭任务。
5. 业务维护通过CLI完成，使用最新CAS及对应确认/依据。测试、消息、Hook closed或Session close都不等于用户关闭Task。

## 通用 JSON Hook

`task-hook`是元数据适配器，面向能显式启动进程并提供 JSON stdin 的宿主。它是本项目定义的协议。Codex 与 pi 原生入口、绑定配置和事件映射见 [原生适配指南](../../integrations/README.md)。未配置 Hook 时手工 CLI 完整可用。

先显式创建/领取并绑定；以下操作只使用示例数据库：

```bash
taskctl --database /tmp/steward-hook-demo/steward.db --json task create DEMO
# 读取输出 version=1
taskctl --database /tmp/steward-hook-demo/steward.db --json task claim DEMO --session local-a --if-version 1
# 读取输出 version=2
taskctl --database /tmp/steward-hook-demo/steward.db --json session bind local-a --source generic --external-session host-a --if-version 2
```

宿主使用参数数组调用，不拼接 Shell；参数中的 Session 和外部 ID 必须来自明确绑定。stdin 为一个事件：

```json
{
  "eventId": "host-event-1",
  "kind": "idle",
  "occurredAt": "2026-09-07T00:00:00Z",
  "message": "这个额外字段会被适配器丢弃，不会存储"
}
```

```bash
task-hook --database /tmp/steward-hook-demo/steward.db \
  --session local-a --source generic --external-session host-a < host-event.json

taskctl --database /tmp/steward-hook-demo/steward.db --json hook list local-a --limit 100
```

- 宿主输入最多 256 KiB；只投影 eventId/kind/occurredAt，加上显式绑定参数组成最多 16 KiB 的标准事件。所有正文、工具参数/结果、自由格式错误、附件等额外字段均丢弃。
- 身份字段只能使用有界 ASCII 标识符，不能放凭据、文件内容或自由文本。来源、时间和事件种类均严格校验。
- 宿主必须提供稳定事件 ID；不能每次重试生成新 ID。相同 ID 不同元数据会冲突。
- busy 时适配器最多重试两次，间隔 100/200 ms；事件写事务使用 100 ms busy timeout。不会持久化重试队列，也不会吞掉失败状态。宿主应显示 stderr/非零退出但继续允许正常 CLI 工作。
- started/resumed/idle/closed 仅代表客户端报告；包括结束之后迟到的事件，都不改变执行生命周期。每个外部 ID 只绑定一个本地 Session，不能借事件跨 Task 改绑。
- 每 Session 上限 10,000 条（含删除后的去重标记）。满时停止接收新 ID并提示，不悄悄驱逐历史；重试已有 ID 仍可判重。需要新的执行会话和新的外部会话标识才能继续独立采集。
- 清除：先 `task show` 获取新版本，再显式执行 `hook clear local-a --if-version <v> --yes`。清除可见记录，保留 session/event ID 与指纹，防止重试复活；不承诺物理擦除，也不释放去重容量。

已有标准事件（包含 schemaVersion/sessionId/source/externalSessionId）可直接使用 `taskctl --json --input event.json hook ingest` 或经认证的 `POST /api/hook`。标准接收接口拒绝未知字段，不能直接把客户端原始消息交给它。

## HTTP 合同速查

默认可信本机直接请求免凭据；远程/严格模式 API 支持 `X-Steward-Token`（脚本/CLI）或浏览器 Cookie；一次性码兑换 `POST /api/connect` 使用 `X-Steward-Connect`。手工首次登录使用请求头凭据调用 `POST /api/login` 建立 Cookie。`POST /api/logout` 撤销当前 Cookie，`POST /api/browser-sessions/revoke` 仅管理员可用。本机免登录或带 Cookie 的写请求要求精确 Origin、`X-Steward-CSRF: 1`；POST 还要求 `Content-Type: application/json`。`GET /api/access` 返回角色 `admin` 或 `reader`，以及 `local` 本机免登录标记。除首次浏览器授权和退出登录外，只读凭据仅允许 GET/HEAD，对所有业务写接口（包括 Hook/Import/Worktree）返回 403 `READ_ONLY`，隐藏按钮仅是 UI 辅助，不代替后端授权。

页面通过同源 fetch SSE 连接 `GET /api/events` 自动刷新；重连后重新取快照，不重放写请求。服务每秒检查只读连接的 SQLite `data_version`，因此 CLI/Hook 的提交也可触发通知；不持有数据库事务，不推送业务内容，每实例最多 16 条订阅且不占普通 API 工作槽位。正在填写的表单保留内容，关闭后再刷新；仍保留手动刷新。尚未提交到 SQLite 的外部 Git 文件变化不触发通知，查看代码现场时仍需手动刷新。

GUI 与 API 同源；跨 Origin、null Origin、非精确 Host 和跨站 Fetch Metadata 均拒绝。默认HTTP 80端口的Origin省略`:80`，Host仅允许绑定IP的等价默认端口写法（带/不带`:80`），不允许其它地址/端口或重复Host。不提供 CORS 放行。当前 HTTP 不支持 Secure Cookie；非回环 HTTP 仍有窃听风险，不能代替 HTTPS。

查询（“已关闭”GUI 视图使用 `status=closed`；CLI 对应 `--status closed`，不是新增 `--view closed`）：

- `GET /api/tasks?view=active|in-progress|blocked|recent&query=...&pageSize=30&cursor=...`；也支持 status/taskKey/fields，view 与 status 互斥。
- `GET /api/tasks/:id`、`/context`、`/notes`、`/history`、`/worktree-status`。
- `GET /api/sessions?taskId=:id`、`/api/sessions/:id`、`/imports`、`/events?after=0&limit=100`。
- `GET /api/doctor`。
- UI 包元数据与静态版本资源使用 `/ui/status` 和 `/ui/releases/:id/:name`，详见 [第 14 篇](14-UI独立发布.md)；不属于业务写接口。

命令使用 `POST /api/commands/:command`，JSON 未知字段拒绝；Task `taskId` 为整数，`expectedVersion` 来自调用方已有快照，不允许服务现读现填。详细字段可直接查看 `crates/server/src/lib.rs` 的严格 `Command` enum。

```json
{"input":{"title":"0907｜功能｜示例任务","goal":"明确下一步"}}
```

上例提交到 `task-create`；下面例子提交到 `task-update`：

```json
{"taskId":1,"expectedVersion":2,"confirmed":true,"reason":"确认补充验收条件","patch":{"nextStep":"补充验收条件"}}
```

命令涵盖 task-create/update/retitle/note/block/unblock/claim/resume/checkpoint/close、session-bind/attach/close/import-add/import-remove、hook-clear 和 worktree-create/adopt/remove/detach。关闭、删除、清除及 Worktree 写操作必须显式 `confirmed:true`；Import 要求 `confirmSensitiveContentReviewed:true`。HTTP 文件路径必须为绝对路径。

业务成功/失败 envelope：`schemaVersion, ok, data, warnings, error`。错误码沿用 CLI；另有 HOOK_EVENT_CONFLICT、HOOK_CAPACITY_REACHED、UNAUTHORIZED、REQUEST_ORIGIN_REJECTED、SERVER_BUSY。Hook 不递增 Task version，绑定和清除则递增；其他 Task mutation 保持原 CAS 合同。

服务不提供请求级幂等 Operation。HTTP 断连/超时不取消或回滚已经开始的业务操作；创建和 Git 写操作的结果必须重新查询确认。对 PARTIAL_EXTERNAL_STATE 展示结构化恢复建议，只能显式执行经过复核的 adopt/detach。

cargo clippy --workspace --all-targets --locked -- -D warnings
cargo fmt --all -- --check
git diff --check

# NODE_PATH 指向包含 playwright 的 node_modules；未设置 channel 则用 Playwright Chromium

测试文件或CI配置存在不表示验收通过。真实客户端信任配置、模型运行、平台及人工业务验收须分别核实；正文/附件不由Hook自动采集。

## 项目管理

后端 `/api/access` 提供项目能力声明；只读页面展示项目/组件/源码、任务归属与组件范围、项目筛选和上下文，不提供业务写入口。详细路由与严格DTO见[第16篇](16-项目与上下文复用.md)，人工流程与环境前置见[第17篇](17-项目管理验收.md)。CLI/API项目维护使用expectedRevision，Task归属使用expectedVersion；reader在解析业务写请求体前拒绝。当前源码为Schema7，不通过普通更新跨Schema切换安装。

## 交接约束

Checkpoint记录当前摘要、已完成事项、决策、待办、下一步及风险；适配器代码、契约测试、配置就绪与真实会话验证分别判断。Hook事件不证明测试通过，任务关闭仍需用户明确决定。
