# 个人偏好与项目规则

## 范围与执行边界

本机个人使用；没有 userId、账号、规则权限、内置模型或自动聊天扫描。Agent 理解明确表达或多个任务反馈，整理、去重、修正后使用 CLI 记录；明确长期偏好可直接 active，歧义推断保持 candidate，临时要求不永久化。无任务来源的直接偏好允许 sources=[]。规则不是项目资料、任务需求、Checkpoint 或执行授权；仓库及父目录 AGENTS 必须独立读取，不由规则 CLI 改写。

规则范围 global 或 project。project 仅在任务当前归属该项目时适用；无项目任务仍读取 global。context 返回全部有效规则，没有自动覆盖、优先级或冲突消解引擎；Agent 必须结合适用范围理解，矛盾时澄清或修正，不从文本推定部署、领取、接管、关闭或远程写授权。

## 存储与校验

数据库 **Schema7** 增加独立两表：

- `rules`：自增 id、scope、可空 project_id 外键、status（candidate/active/disabled）、独立 revision、content_version、content_json、created_at、updated_at。global 必须 project_id=NULL，project 必须引用有效项目；revision 初始1。
- `rule_history`：自增 id、rule_id 外键、revision、operation、reason、before_json、after_json、occurred_at；`UNIQUE(rule_id,revision)`。创建 before=NULL，更新/停用保留含完整来源的前后快照。操作分别为 rule.created / rule.updated / rule.disabled。

所有规则写入在一个 IMMEDIATE 事务内校验、CAS、写规则与历史。失败全部回滚，不递增 Task version 或 Project revision，不创建/修改 Session。更新是完整替换，不是 Merge Patch；可调整范围、项目、状态和正文。相同内容/状态作为无变化拒绝；停用也必须携带最新 revision。没有删除或自动重试。

数据库content_version仅约束正整数，不将未来内容格式与数据库迁移绑定；当前应用支持格式1，写入或读取未知版本均明确失败。Schema7为未发布候选，不为修订候选约束另增schema版本；早期Schema7合成库不自动ALTER，应使用当前初始化器重建隔离夹具，正式Schema6仍走显式复制。未知字段、类型错误和非法 UTF-8/JSON 拒绝。CLI 输入最多128 KiB，content 序列化 JSON 最多65536字节；name 1..300、body 1..48000、reason/evidence 1..4000 UTF-8字节，必须非空白且不含 NUL。sources 必填数组、最多32条，完全相同的来源条目拒绝。无逐偏好数据库字段。

```json
{
  "scope": "global",
  "projectId": null,
  "status": "active",
  "contentVersion": 1,
  "content": {
    "name": "合成偏好示例",
    "body": "自由 Markdown 正文，不表示真实用户偏好。",
    "sources": [
      {"kind": "explicit", "evidence": "合成的明确长期表达", "taskId": null, "taskVersion": null},
      {"kind": "inferred", "evidence": "合成历史反馈", "taskId": 1, "taskVersion": 2}
    ]
  }
}
```

来源 kind 为 explicit/inferred；taskId/taskVersion 同时为空或同时为正整数。引用任务必须存在，版本不能晚于当前版本；允许历史版本和跨项目、多任务来源，不声称来源版本当前仍相等，也不校验或重建历史聊天原文。示例来源任务必须替换为测试库中真实存在的记录，或使用 sources=[]。来源、正文、原因、历史均不得包含密码、Token、Cookie、授权头或隐藏推理；没有自动秘密检测或内容加密保证。停用不会抹除历史。

## CLI

以下命令仅展示合同；DB 为明确指定的隔离数据库，ID/REV 来自刚读取结果。

```text
taskctl --database DB --json rule list [--scope global|project] [--project PROJECT_ID] [--status candidate|active|disabled]
taskctl --database DB --json rule show ID
taskctl --database DB --json rule create --input rule.json --reason REASON
taskctl --database DB --json rule update ID --if-revision REV --input rule.json --reason REASON
taskctl --database DB --json rule disable ID --if-revision REV --reason REASON
taskctl --database DB --json rule history ID
```

list 默认所有范围与状态，多个过滤条件取交集，不隐式隐藏候选/停用规则。规则使用数字 ID；查询不写“已阅读”记录。JSON envelope 保持 schemaVersion:2；show/create/update/disable 返回 data.rule，list 返回 data.rules，history 返回 data.rule 和 data.history。人类模式完整打印结构化结果。

CAS 冲突为 VERSION_CONFLICT，exit4，details 为 ruleId、expectedRevision、currentRevision 和当前 rule；重新读取并重新判断，不盲目重试。规则输入错误为 INVALID_INPUT，存储规则解码/格式错误为 DATABASE_UNAVAILABLE；读取错误不伪装成空集合。

## 同一上下文入口

```text
taskctl --database DB --json task context TASK --require-read-only
taskctl --database DB task context TASK --format markdown
```

Herdr 分发窗口与人工新开窗口都使用这个入口；先取需求、版本和规则，再决定是否另行执行显式 Task mutation。只读查询不 claim/resume、不写阅读状态、不导入聊天、不关闭任务。

`Service::task_context` 专用 READ_ONLY|NOFOLLOW 连接，不调用普通初始化器，不修改权限或journal_mode。只接受已存在的当前Schema普通库，复核本地路径、sidecar与文件身份；空文件、非空Schema0、无效/旧库、缺库/缺任务均失败，不创建目录、数据库或表。`--require-read-only` 让旧CLI在解析阶段拒绝，不回退旧调用。合法库读取已提交WAL；SQLite可能创建/更新SHM，不承诺所有sidecar零活动，不使用immutable或忽略WAL规避。

在读取 Task/Project/Checkpoint/Notes 的同一个数据库读事务内取得 `sessionRules: {formatVersion:1,rules:[...]}`；条目包含 ID/revision/scope/projectId/contentVersion/content（名称、完整正文、完整来源），以及状态和时间。只带 active；candidate/disabled 不成为执行要求。无规则是成功空数组；错误使查询失败，不截断必读规则或静默降级。Task 换项目后下次查询自动采用新项目规则。CLI Markdown、JSON、task resume 的返回、Web上下文复制均携带规则；resume 保留其原有显式 CAS/Session 写语义，不是只读入口。

规则修正后后续 context 读取新 revision，停用后不再带入。context 没有缓存或读取标记。SQLite SSE 观察 data_version，因此 CLI 规则写入也触发既有 Web只读刷新，不要求修改任务版本。

**实际候选入口**：[integrations/pi/task-context.ts](../../integrations/pi/task-context.md)可由Herdr原生Agent参数或手工Pi启动显式加载，使用同一个Pi input门控预检task context，不改写输入；技能/模板展开后在context事件交付瞬时完整快照。失败明确阻断输入，注入时身份变化触发当前Agent abort；不依赖被宿主吞掉的扩展异常。真实Pi新会话的最终模型请求已用隔离合成provider验证，不是Service对象重建测试。入口不关联或领取任务，要求明确候选CLI/已存在数据库/数字任务，IO前后复核Session/cwd，不向已有聊天或切换后的会话注入旧目标。观测适配器保持独立。

## 只读 Web / API

- `GET /api/tasks/:id/context`、`GET /api/projects/:id` 返回 sessionRules；`GET /api/access` 增加 sessionRules:true 能力标记。
- 沿用现有 HTTP身份与读取合同；不新增规则写 HTTP 路由或 Web业务表单。此能力不引入个人规则账号模型。
- 活动源码 UI 为 React，构建到 web/dist，显式同步到 crates/server/web-readonly 内嵌快照；旧原生与 web-legacy-readonly 不作为当前发布入口。
- 任务/项目概览完整展示有效规则、历史来源与 revision；Markdown 正文安全地按纯文本展示，不执行 HTML。缺字段/不支持格式与空规则明确区分。
- UI API 合同 **4**，包格式仍1、JSON envelope仍2。旧合同1/2/3包和携带旧合同头的请求拒绝，防止旧 UI 复制任务时漏掉规则；不能改 manifest 数字冒充兼容包。无 UI合同头的既有 CLI/API消费者保留新增字段兼容，须自行采用 context新字段。

## Schema6 → 7 复制、备份及恢复

普通写连接只初始化空库，不原地升级；task context的专用只读连接拒绝空库。Schema2/4/5 的现有显式复制目标也是 Schema7。Schema6 使用：

```text
taskctl --database NEW_ABSOLUTE_DB --json --yes database import-schema6 --source QUIESCENT_SCHEMA6_DB
```

源必须停写、路径本地绝对且可信；目标及 sidecar 必须不存在，父目录私有。以冻结 schema6.sql（LF行尾由.gitattributes与测试固定）严格比对源表/索引/触发器/约束结构，在固定只读快照中复制14个旧表与9类自增高水位到私有暂存新库；逐字段及 typed hash 比对、外键、integrity_check、应用解码验证。新 rules/rule_history 断言为空，不推断历史规则、任务状态或项目归属。失败不发布目标，成功以不覆盖方式发布，不升级源、不观察历史外部路径、不安装或切换服务。Schema7 与旧 schema_migrations v7 归档不是同一种源；后者仍走 import-v7 的独立合同。

权限、WAL、身份复查、并发写检测与故障边界沿用[显式复制合同](18-Schema2到4迁移与隔离演练.md)。返回 sourceSchema/targetSchema、counts、highWaterMarks、tableSha256、verified；sourceQuiescenceVerified:false，不声称已证明停写。

正式维护须另行授权：暂停 CLI/Hook/taskd/宿主适配器等全部写入者，使用 SQLite一致备份纳入已提交 WAL，禁止只复制运行中的主库文件。保留可由旧工具恢复的停写备份和旧安装，验证新库后成套切换 CLI/Hook/taskd/UI及明确路径；Windows新启动器只接受 Schema7，旧安装不能普通跨 schema更新，新安装根目录独立。不承诺旧进程的活连接会被版本检查自动阻断。

恢复写入前可在停写状态按核验方案恢复旧库/旧工具；Schema7接受新写入后不能仅降级二进制或覆盖旧备份，需再次停写、保留两侧数据并明确选择修复前进或对账。未实现向Schema6降级或规则历史反向合并。
