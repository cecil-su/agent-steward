# 个人偏好与项目规则

## 范围与执行边界

本机个人使用；没有userId、规则账号权限、内置模型或自动聊天扫描。Agent整理明确表达或任务反馈，去重并核实后通过CLI记录；明确长期偏好可active，歧义推断保持candidate，临时要求不永久化。无任务来源的直接偏好允许sources=[]。

规则不是项目资料、任务需求、Checkpoint或执行授权；仓库及父目录AGENTS必须独立读取。范围为global或project；project规则仅在任务当前归属该项目时适用。context返回全部有效规则，没有自动覆盖、优先级或冲突消解引擎；矛盾须澄清，不从文本推定部署、领取、接管、关闭或远程写授权。

## 存储与校验

Schema7包含：

- `rules`：自增id、scope、可空project_id外键、status（candidate/active/disabled）、独立revision、content_version、content_json、created_at、updated_at。global的project_id为NULL，project引用有效项目；revision初始1。
- `rule_history`：自增id、rule_id外键、revision、operation、reason、before_json、after_json、occurred_at；UNIQUE(rule_id,revision)。创建before=NULL，更新/停用保存完整前后快照。操作为rule.created/rule.updated/rule.disabled。

写入在一个IMMEDIATE事务内校验、CAS并保存规则/History，失败全部回滚；不递增Task version或Project revision，不创建/修改Session。更新为完整替换，可调整范围、项目、状态和正文；相同内容/状态拒绝。停用须最新revision，没有删除或自动重试。

数据库content_version约束为正整数，应用仅支持格式1，未知格式读写明确失败。未知字段、类型错误和非法UTF-8/JSON拒绝。CLI输入最多128 KiB；content序列化JSON最多65536字节。name为1..300、body为1..48000、reason/evidence为1..4000 UTF-8字节，须非空白且不含NUL。sources必填、最多32条，完全重复的来源拒绝。

```json
{
  "scope": "global",
  "projectId": null,
  "status": "active",
  "contentVersion": 1,
  "content": {
    "name": "合成偏好示例",
    "body": "自由Markdown正文，不表示真实用户偏好。",
    "sources": [
      {"kind": "explicit", "evidence": "合成明确表达", "taskId": null, "taskVersion": null},
      {"kind": "inferred", "evidence": "合成任务反馈", "taskId": 1, "taskVersion": 2}
    ]
  }
}
```

kind为explicit/inferred；taskId/taskVersion同时为空或同时为正整数。引用任务须存在，来源版本不能晚于当前版本；允许跨项目、多任务及已保存版本来源，不声称来源版本仍为当前版本，不重建聊天原文。示例任务须替换为隔离库真实记录或使用sources=[]。正文、来源、原因及History不得包含秘密或隐藏推理；没有自动秘密检测或内容加密保证，停用不抹除已保存记录。

## CLI

DB为显式隔离库，ID/REV来自刚读取的结果。

```text
taskctl --database DB --json rule list [--scope global|project] [--project PROJECT_ID] [--status candidate|active|disabled]
taskctl --database DB --json rule show ID
taskctl --database DB --json rule create --input rule.json --reason REASON
taskctl --database DB --json rule update ID --if-revision REV --input rule.json --reason REASON
taskctl --database DB --json rule disable ID --if-revision REV --reason REASON
taskctl --database DB --json rule history ID
```

list默认所有范围/状态，过滤取交集。使用数字ID，查询不写阅读记录。JSON envelope2；show/create/update/disable返回data.rule，list返回data.rules，history返回data.rule及data.history。人类模式完整打印结构化结果。

CAS冲突为VERSION_CONFLICT、exit4，details含ruleId、expectedRevision、currentRevision和当前rule。输入错误为INVALID_INPUT，存储规则解码/格式错误为DATABASE_UNAVAILABLE；错误不伪装成空集合。

## 同一上下文入口

```text
taskctl --database DB --json task context TASK --require-read-only
taskctl --database DB task context TASK --format markdown
```

读取需求、版本与规则后，再决定是否执行显式Task mutation。查询不claim/resume、不写阅读状态、不导入聊天或关闭任务。

`Service::task_context`使用READ_ONLY|NOFOLLOW连接，不初始化、不修改权限或journal_mode。只接受已存在且格式受支持的普通库，复核本地路径/sidecar/身份；空文件、非空Schema0、不兼容库及缺失库/任务拒绝。`--require-read-only`要求客户端支持专用只读入口，不回退不支持该选项的调用。SQLite读取已提交WAL时可能涉及SHM，不承诺全部sidecar零活动，不用immutable或忽略WAL规避。

同一数据库读事务取得Task/Project/Checkpoint/Notes及`sessionRules:{formatVersion:1,rules:[...]}`。条目包含ID/revision/scope/projectId/contentVersion/content、状态与时间，正文和来源完整；只带active，空规则是成功空数组，错误使查询失败。换项目后按新的归属读取，不截断必读规则。

CLI Markdown/JSON、resume返回及Web复制包含规则；resume仍为显式CAS/Session写操作。规则更新或停用后，下次context直接读取有效结果，无缓存或阅读标记。SSE观察data_version，规则写入可触发Web刷新，不修改任务版本。

## 宿主接入边界

[`integrations/pi/task-context.ts`](../../integrations/pi/task-context.md)为显式加载入口，可由Herdr Agent参数或手工Pi启动使用。Pi input门控预检同一个task context，不改写输入；技能/模板展开后在context事件交付瞬时完整快照。预检失败阻断输入，注入时身份变化触发当前Agent abort。

入口要求明确CLI、已存在数据库和数字Task；IO前后复核Session/cwd，不关联、领取或向切换后的会话注入目标。观测适配器独立。外部全局安装是否加载该入口须现场核对，不能从仓库实现推定所有宿主已自动接入。

## 只读Web / API

- `GET /api/tasks/:id/context`和`GET /api/projects/:id`返回sessionRules；`GET /api/access`提供sessionRules:true能力标记。
- 没有规则写HTTP路由或Web表单，不引入个人规则账号模型。
- React源码为web/src，内嵌快照为crates/server/web-readonly；外置包由UiStore按兼容合同托管。实际采用包须查询目标/ui/status，不由源码推断部署状态。
- 任务/项目概览及复制上下文完整展示有效规则、来源和revision；正文按纯文本展示，不执行HTML。缺字段/不支持格式与空规则分开处理。
- UI API合同4、包格式1、JSON envelope2。不匹配包和带不匹配合同头的请求拒绝；不能只改manifest数字。无UI合同头的CLI/API调用者仍须遵守当前接口并读取完整context字段。

## 导入与恢复

普通连接只初始化空库；task context拒绝空库。Schema6输入命令为：

```text
taskctl --database NEW_ABSOLUTE_DB --json --yes database import-schema6 --source QUIESCENT_SCHEMA6_DB
```

严格按冻结schema6.sql核验，在只读快照中复制14表及九类自增高水位到Schema7私有暂存库，逐字段/typed hash、外键、完整性及应用解码核验；rules/rule_history为空，不推断规则或任务状态。Schema2/4/5命令也以Schema7为目标；准确列表、归档输入区别、WAL/权限/路径与发布限制见[隔离导入](18-Schema7隔离导入与验证.md)。

复制不停止写入者、不安装/切换服务。正式维护须独立停写、备份、核验并成套切换；版本检查不能阻止已有连接。新库接受写入后不得只降级二进制或覆盖备份，没有向输入格式反向合并规则History的实现。
